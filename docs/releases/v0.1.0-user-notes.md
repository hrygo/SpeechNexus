# SpeechNexus 0.1.0

第一个可以用起来的版本：**在这台机器上起一套语音服务，上传音频能转成文字，给一段文字能读成
语音，长任务能建成 Job 并拿回制品文件。**

这不是一个「功能齐全」的版本。它是一个**边界写得清楚、能自己跑起来、坏了知道去哪看**的版本。
下面按「能干什么 → 怎么起 → 不能干什么 → 最可能踩的坑」写，细节都给了链接。

> 面向工程验收的完整证据（每条能力对应哪次真实部署、哪个读数、哪些还没验）在同仓库的
> [发布说明（工程版）](https://github.com/hrygo/SpeechNexus/blob/v0.1.0/docs/releases/mvp-0.1.0.md)。
> 本页只讲使用者要的。

## 这个版本能干什么

| 想做的事 | 怎么用 | 说明 |
| --- | --- | --- |
| 把一段音频转成文字 | `POST /v1/audio/transcriptions`（同步，一次请求一次结果） | 需要先起引擎并注册；参考部署上是真实引擎跑通的 |
| 把一段文字读成语音 | `POST /v1/audio/speech`（同步） | 需要一个已发布且资格有效的音色 |
| 传文件建长任务、回头取结果 | `POST /v1/nexus/jobs` → `202`，再读 Job 与制品 `GET …/content` | 这是异步主链：上传资产 → 建 Job → 后台执行 → 产物可下载 |
| 在浏览器里用 | 起 `workbench` / `admin` 两个 Web 入口 | 页面与后端版本不一致时会告警，但不会拒请求 |
| 删掉内容 | 工作台侧的删除计划 → 删除（带预检、确认、账本） | **仅工作台侧**；语音侧删除不在本版本 |
| 看服务是否健康 | `/healthz`、`/readyz`、`GET /v1/nexus/version`、`GET /v1/nexus/admin/diagnostics` | 注意 `/readyz` 不代表「能建 Job」，见下面第 2 条坑 |

## 这个版本不能干什么

列出来不是免责，是让你不用白试：

- **实时语音会话**（`/v1/realtime` 等）——占位，不可用。
- **语音侧的内容删除**（`/v1/nexus/deletion-plans`、`/v1/nexus/deletions`）——本版本恒返回
  `503`。工作台侧的删除可用。
- **声音设计/克隆的完整流程**——引擎接受面在，产品级泳道不在本版本。
- **多机部署与故障演练**——只验了单机单 workspace。
- **浏览器全矩阵**——只验了 Chromium 无头。
- **`GET /v1/models` 的 `admission_state` 当作「现在能不能建 Job」**——它不是这个意思（见坑 2）。

## 最可能踩的 5 个坑

1. **升级后，老的内建音色突然用不了了。** 迁移前产生、没有来源记录的音色资格不再被接受，同步
   TTS 会答 `404 voice_not_found`。处置：给**新的**音色版本重新取资格再发布，同一个版本不能补发。
2. **`/readyz` 是绿的，但建 Job 返回 503 / 429。** `/readyz` 不反映 Job 准入可用性，也不反映
   有多少容量被没结清的取消占着。判断「能不能建 Job」请看 `POST /v1/nexus/jobs` 的实际应答码，
   或 `GET /v1/nexus/admin/diagnostics` 里的 `cancellation_debt`。
3. **对一个已经成功的执行点了取消。** Job 会停在 `cancelling`、容量槽不归还；默认部署**不启动**
   取消对账 worker（`SPEECHNEXUS_JOB_CANCELLATION_RECONCILIATION_ENABLED=false`），所以它不会自己
   好。重试预算用尽后这条记录会被标成 `exhausted` 并不再被领取——只能走操作员出口。
4. **启动失败时把整段输出贴到公开的地方。** `api`、`gateway`、`job-dispatch-worker` 的失败是
   traceback，里面原样带驱动的连接报文（含主机、端口、角色名，口令错时还带
   `password authentication failed`）。要贴就只贴 `FAIL:` 行和异常类型名。
5. **同步转写的槽位不归还，且没有「强制释放」。** 引擎提交状态未知、缺停止/清理证据、路由不匹配
   这几类，自动结算不会替它们下结论，槽位一直被占；`asr_settlement_debt` 能看到它们，但没有
   强制释放入口。别用「同步 ASR 成功率高」推断「槽位从不被占」。

**完整的 16 条已知限制**（每条都写「会踩到什么 → 怎么处置 → 依据」）在
[发布说明（工程版）§6](https://github.com/hrygo/SpeechNexus/blob/v0.1.0/docs/releases/mvp-0.1.0.md#6-已知限制)。

## 升级与回滚

- 升级顺序、迁移行为、每一步该看到什么信号：
  [工程版 §4](https://github.com/hrygo/SpeechNexus/blob/v0.1.0/docs/releases/mvp-0.1.0.md#4-升级)。
- **迁移不可回退**（`alembic downgrade` 被显式拒绝），回滚是指「回到旧镜像」而不是「回退数据库」，
  且旧镜像面对新 schema 的行为有明确边界：
  [工程版 §5](https://github.com/hrygo/SpeechNexus/blob/v0.1.0/docs/releases/mvp-0.1.0.md#5-回滚)。
- 升级后如果某个角色启动被拒、某个探针整体变成 `unavailable (permission)`，通常是**授权没跟上**
  而不是故障：按[工程版 §4.3](https://github.com/hrygo/SpeechNexus/blob/v0.1.0/docs/releases/mvp-0.1.0.md#43-每一步的可自查信号)
  重跑对应的 `*_grants`。

## 版本标识怎么核对

- 标签：`v0.1.0`（附注标签），`git rev-list -n 1 v0.1.0` 拿到提交，别凭本页推断。
- 服务自报：`GET /v1/nexus/version` 与 `/healthz` 的 `version` 是 `0.1.0.dev0`；
  `contract_digest` 是契约树的摘要，用于判断「两台机器是不是同一套契约」。
- **摘要会随契约修订变化**，同一个版本号在不同提交上可能不同——要「同版」，比对的是提交，不是版本号。

# SpeechNexus 多 Agent 协作与职责边界

GitHub 保存产品需求、原始验收条件、代码审查和合并事实；执行切片、候选、工作区与接收结论保存在对应 issue、PR 和临时检出中，不另建平台任务队列。产品进展以同版公开业务链和 AC 证据判断，任务数量、绿色 CI 和健康检查各自只证明覆盖范围。

按[交付 SOP](agent-delivery-sop.md)选择当前 Codex 会话、subagent 或独立会话：一项切片一位交付负责人，普通局部工作直接完成；需要隔离上下文、并行独立工作或独立验收时才委派。需要真实 Linux GPU 环境时，可经 Paperclip 通道委托 GPU Agent 执行，该通道是可选执行位置，不是项目队列或必需依赖。技术负责人不增加产品排序权，所有执行共用一条队列和资源额度；本页维护角色职责、环境与证据边界。

产品实施围绕同版公开业务链和 AC 交付，当前阶段、链路状态及关键路径以最新明确授权、[总控 #336](https://github.com/hrygo/SpeechNexus/issues/336)和当期候选证据为准，不由长期规则固化。2026-10-27 的默认语音装配 503 与 Job 缺消费者记录见 [#254](https://github.com/hrygo/SpeechNexus/issues/254)及[事故记录](../archive/operations/paperclip/runtime-incidents.md)；它们是历史发现，不证明当前状态。[闭环整改计划](../archive/plans/2026-10-27-delegra-legion-closed-loop.md)等历史平台方案保留原时点事实；Paperclip 仅作为 GPU 委托执行通道保留，其任务卡、编号、面板和岗位模型不承担项目队列、AC、环境配置或门禁入口。

## 决策与执行结构

用户保留重大范围决定、合并授权和最终 Gate / 投产放行。项目内由承接当前工作的**一个 Codex 会话**承担 SM+PO 职责：决定产品价值、优先级、迭代目标、范围、AC、执行排序及对用户的承诺，直接向适任角色派工。同一时刻只有一个承接会话；原产品总控会话可按需承担独立架构 / 风险审查或备用接管，接管须有新的明确安排。

角色是职责集合，由当前会话、subagent 或独立会话承担，不构成平台岗位、固定 Agent 数量或汇报关系：

| 角色 | 主要职责 | 承担方式 |
| --- | --- | --- |
| 项目负责（SM+PO） | 产品目标、优先级、范围与 AC、唯一执行队列、派工及接收结论 | 当前 Codex 会话；用户保留重大决定与放行 |
| 契约与集成 | 公开契约 / 生成链、权威状态 / 事务、复杂持久恢复、跨层装配和本机集成 | 当前会话或 subagent；[简报](roles/contract.md) |
| 执行与 GPU | 网关 / 控制器、执行身份与限额、停止 / 释放、Linux / 隔离持久验证和真实 GPU | Linux GPU 主机上的 GPU Agent（Paperclip 委托）或独立会话；[简报](roles/execution.md) |
| 独立验收（QA） | 最终固定候选的正式消费者、浏览器、故障与适用设备验证 | 与作者不同的会话或主机；[简报](roles/qa.md) |
| 工作台 | 边界明确的 Web / Workbench、正式协议消费、状态与恢复体验 | 当前会话或 subagent；[简报](roles/workbench.md) |
| 集成交付 | 指定候选的依赖核对、产物接收、补丁接入及集成建议 | 按需委派；[简报](roles/manager.md) |
| 交叉审查 | 固定问题的独立方案 / 代码反证 | 按需审查会话；[简报](roles/reviewer.md) |
| 证据与文档 | 复杂 manifest / 原件接收、证据映射、文档同步及 issue 差异草稿 | 按需委派；[简报](roles/evidence.md) |
| 独立架构 / 风险审查 | 明确委派的架构、恢复及验收反证 | 按需独立会话；未委派时空闲 |

角色可由同一会话兼任，但审查独立性按「是否参与该候选实现」和「是否具备独立上下文 / 模型」判断，不由角色名、subagent 名称或上下文继承关系推定。角色简报与[共用边界](roles/common.md)是派工时的提示材料，不是注册岗位；模型、工具、环境与权限以宿主实际能力和当前任务授权为准，不从简报、历史配置或岗位名推断。

## 一条执行队列与独立接收

GitHub [总控 #336](https://github.com/hrygo/SpeechNexus/issues/336)及交付 issue 直接说明当前范围、事实与 AC；[本地矩阵](../plans/delivery-tracking.md)只读汇总状态、缺口、依赖及证据。承接会话维护一条执行队列，只接入已批准目标的当期切片，不镜像创建全部长期工作包，不额外维护产品 backlog；subagent 不持有独立队列，返回值即结论。计划和报告解释版本、依赖及证据，不成为第二份排序权威。

派工前写清：

1. 已授权目标及决策来源、GitHub issue / AC、触发场景、预期结果和排除范围。
2. 实际完整 base SHA、目标分支、输入契约 / 制品版本，以及接收方可取得的输入。
3. 交付负责人、唯一写者与文件范围、适任非作者 reviewer、接收者；仅回传路径另指定集成写者。
4. 执行位置与身份、当前能力回执、准确环境入口、资源窗口、允许的运行态动作和禁止事项。
5. 按风险选择的验收、原始证据、失败退出条件、具名解阻方和 GitHub 上的审核 / 接收路径。

必要依赖在派工前写明解除条件；父子关系、关联链接或整包未关闭不自动形成门禁。单个环境故障只阻塞受影响动作，无关独立项继续。

派工前复用仍有效的同配置 / 同环境能力回执，仅在首次使用、相关变更或失败后做最小预检，核当前资源窗口与实际运行；不为每个任务另建探针卡或侦察 subagent。分组测试在 issue 维护累计清单，明确子进程、内存 transport、临时 loopback 与持久服务各自的实际副作用和授权，避免因边界措辞不清反复拆任务。

作者按授权提交并尽早建立草稿 PR；只能回传时由预定集成写者核验接入并建立 PR。独审和可并行验证围绕固定候选开展，返修更新原 PR；QA 按风险验证最终候选并交报告，SM+PO 汇总专业结果并判断产品接收。常规切片不必调用集成交付角色。返修留在原切片，审查结果属于 reviewer 的报告，不改写作者原始证据。

- 普通局部改变由一名适任非作者审查，检查范围随风险选择，不要求全员会签。
- 协议、原子事务、恢复、fencing、停止或预算释放等高风险改变保留非作者审查及对应环境验证，优先使用不同模型或独立会话。通常契约写 → 执行审、执行写 → 契约审；第二视角按需选用。
- 契约与执行两个角色均参与实现时，保留独审缺口，明确委派未参与该候选的合格审查者；不由作者换角色自签。SM+PO 不因负责调度而自动充当技术 reviewer。
- QA 验证最终候选的用户结果，不代替代码审查；作者自测不能冒充独验。文档和低风险局部改变不固定占用完整 QA 窗口。
- 目标分支或补丁变化后，记录新候选及新增差异，只补验受影响的结论。旧 SHA 的审查不能直接放行不同字节。

## 执行环境与制品

主机分工是工作约定，不代表当前主机、服务和容量已就绪；执行前按当前授权核验能力卡与部署映射。本机承担协调、主要开发 / 集成及适用 macOS 检查；MegaCube 承担 Linux aarch64、隔离数据库 / 对象存储与真实 GPU；MacBook 承担轻量独立消费者 / 浏览器验证。区分 agent 执行主机、被测服务和产品目标拓扑，不把三台开发机器视为已验的多 GPU 集群。

需要 Linux GPU 或隔离持久环境而本机不具备时，经 Paperclip 委托 GPU Agent 执行：任务卡只承载本次执行，派发前核对通道可达、GPU 与台账条件、输入可取得及具名接收者；执行结果由接收者核对候选、命令、退出码和限制后落回 issue / PR。通道或任务状态失败不改变项目队列判断，也不作为交付证据。

能力卡记录工具 / OS / 架构、可用服务、核验时间、资源类别 / 峰值、保留服务及当前余量。统一内存、常驻模型、KV、音频与测试峰值一起核算；GPU 利用率零、显存 N/A、标称内存和 swap 都不授予加载容量。本机共享推理、磁盘和浏览器，MacBook 一次一个轻量浏览器 / 设备窗口；重型 CPU 与 GPU 实验默认错峰。

任务明确 `SPEECHNEXUS_TOOLCHAIN_ENV` 的实际入口。执行者先激活环境，核对 `pwd`、完整 HEAD、工作区状态与版本，每个 checkout 安装自己的锁定依赖；缓存不等于当前依赖已安装，不链接其他 checkout 的 `.venv` 或 `node_modules`。仅加载该角色与切片所需规则、技能和验证范围，不强制所有角色读完整管理手册或所有技能。

具备能力的执行位置直接 commit / push / 建 PR；仅回传的路径由预定集成写者接收并完成授权内提交。交接包含完整候选 SHA 或可核验的制品身份、输入版本、实际命令与原始结果、未验项和下一接收人。仅在传输边界需要时提供完整 base、patch、新文件及大小 / 摘要清单；已在远端 PR 保存的同版代码不重复打包。产物必须在获准存储可取得，接收方实际下载并核验，不能只交发送方本机路径。补丁接入时记录来源 base / patch hash、目标 SHA、接入新增差异和最终候选 hash。失败保留产物和恢复点，不重做语音业务或补造最终提交。

## 权限、预算与证据边界

同时最多两个无写冲突开发切片，并受真实主机窗口约束；同一写者同时只推进一个切片。审查与文档也计入资源，队列约定不是 OS 硬锁。subagent、独立会话与 GPU 通道消耗同一模型和主机额度，增加调用层数不增加额度。

模型 ID、实际思考级别、工具能力及有效环境须按宿主配置和一次实际调用核验，不能用模型名、Harness 名或后缀推断资格。任务分配、skill 创建与远端写入权限分别检查，模型可用不证明这些权限适当或工具链可用。

选中 skill 只提供指令，不安装工具或增加 MCP、浏览器、网络及写入权限。只读 / 离线角色不应被要求主动发反馈、安装依赖或运行其没有的工具。风险限定和宿主已有证据规则适用于通用审查 / 验证流程，不把每次消息都变成全量新测试。

无可推进事项时不新建轮询、自动巡检或空转 subagent；原因或输入改变并取得新证据后续行。配置 / 鉴权 / 工作区同因失败不循环重试，保存诊断交具名成员处理。

真实音频、转写、书稿、声音参考与业务派生内容留在部署网络和批准存储，不进入 agent 提示、外部模型、平台附件或 GitHub；验证使用合成或最小脱敏输入。凭据走批准的受管引用，能力卡和交接不复制秘密。保护既有模型、数据库与其他共享服务，不把本机共享库改作项目测试库。

证据分列契约 / fake、生产装配、隔离持久行为、公开真实引擎、浏览器 / 设备、物理多机及质量 / 许可 / 运维，标注版本、环境、通过 / 失败 / 跳过 / `not_run`。公开上传 → 实际音频 ready → 权威配置 / Job / 原子准入 → 真实执行 → 原身份发布 → SDK / 页面下载仍按原 AC 验收。首轮 TTS 硬上限候选及 GPU 回归不替代公开两链或 Gate。

## 角色简报与变更

角色简报由[共用边界](roles/common.md)与各角色聚焦正文组成，只保留职责、执行边界、交付与收尾。派工给 subagent 或独立会话时引用对应正文并补任务上下文，不复制整本管理手册，也不假设 subagent 自动获得独立 checkout、隔离环境或额外权限。

简报随代码维护：修改走 Git 提交与审查，按提交恢复；不维护平台版本号、逐岗配置回读或私有部署映射。私有身份、机器私有路径和内部入口留在仓库外部署记录，不写入公开源。

回退先停止相关 subagent 或会话、保留运行与产物，再恢复本次提交前的规则版本；不重置 Git、不删除历史或产品数据，不自动恢复已失效的旧队列或历史暂停。提交、PR、合并、发布及运行态变更分别按当前授权执行。

## 运行期规则与已踩的坑

历史执行事故、当时命令、失败及后续证伪保存在[运行事故与历史排障](../archive/operations/paperclip/runtime-incidents.md)，仅在相关排障时读取，不作为常规派工前置。当前派工、预检、等待及安全恢复统一按[交付 SOP](agent-delivery-sop.md)执行；历史「清空会话 / 新建任务卡恢复」等做法不构成当前操作授权或未知结果重放依据。

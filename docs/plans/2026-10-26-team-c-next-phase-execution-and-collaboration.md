### 2.2 每个执行单元的协作循环

1. **开始时核对：**C 读取相关 A/B 会话、issue 与已交付制品，固定本单元共同 SHA、输入、消费者、预期结果和写入范围；已有证据仍有效时复用。
2. **按需请求：**缺项写成一条具名依赖，包含 owner、所需接口/制品、版本或摘要、解除条件、受影响 AC、C 当前可继续的工作。发送获授权后，向上述既有会话提出具体请求；接口不可用时保留待发送内容并如实报告。
3. **确认接收：**接收方返回“可消费/部分可消费/不可消费”、对应版本、实际验证与限制。候选代码、本地摘要、注册输入、发布和资格分别标注，不能只回复“已支持”。
4. **消费反馈：**C 复验正式入口，问题按所有权回交；先修接口或实现差异，不通过夹具、放宽校验、直写底座表来掩盖。
5. **结束时记录：**分别更新任务进展与 AC 证据，列出新增事实、未验证项、下一步和依赖变化；远端写入获授权后写回原跟踪项并回读。对无变化的等待不重复空轮询，后续以制品、版本或环境变化触发复核。

共享写入点遵守单一维护者：A 维护公共 speech/admin 契约、生成器和迁移框架，B 维护执行/流及停止事实契约，C 维护 workbench 契约和业务语义；共享 CI/锁文件/部署与组合根由 A 指定集成维护者串行接收。同一位置出现未知并行改动即暂停该处写入并核实。接口或架构争议先提交具体差异、影响与方案；用户决定范围和 Gate 放行。

### 2.3 首条 CustomVoice 与取消结算的接收边界

本节依据 `54daef6…` 的[CustomVoice 交接](https://github.com/hrygo/SpeechNexus/blob/54daef6ae4792b69a0e5e8645b09240ff715082e/docs/architecture/file-tts-binding-handoff.md)、A/B 反馈及本轮读取的机器契约。声明、部署要求与实际资格分别记录，不从较宽的公共 schema 推断某个 binding 的能力。

| 范围 | 已确认的声明或证据 | 本阶段接收条件与 owner |
| --- | --- | --- |
| 文本与调用次数 | 首条 CustomVoice 一次 intent 一次合成，最多 400 codepoints；不提供长文本切分 | A/B/C 对齐注册、准入、命令与页面计数；覆盖 400/401、非 BMP 等 Unicode 边界及超限拒绝。公共 Job 的较大文本容量不扩大此 binding；长文本另行编排并验收，不在同一 intent 内多次外发绕过 |
| 本次支持域 | `zh`/`en`，速度 0.5–2.0，24 kHz mono PCM16；MP3/WAV/PCM；首条 builtin 声音由 A 提供匹配修订 | C 按实际权威 binding 和资格展示支持域。声明不证明每种语言、速度、格式及其组合均取得真实质量/容量资格 |
| Nexus 指令 | [TtsOverrides.instructions](https://github.com/hrygo/SpeechNexus/blob/54daef6ae4792b69a0e5e8645b09240ff715082e/contracts/shared/speech-overrides.schema.json#L99) 的 `maxLength=2000` | A/C 按所用入口校验，再结合 binding 有效上限；不能统称所有公共/内部命令均为 2000 |
| 标准接口与内部命令指令 | [标准 speech 接口](https://github.com/hrygo/SpeechNexus/blob/54daef6ae4792b69a0e5e8645b09240ff715082e/contracts/speech-openapi.yaml#L2276)及[内部执行命令](https://github.com/hrygo/SpeechNexus/blob/54daef6ae4792b69a0e5e8645b09240ff715082e/contracts/internal/execution-command.schema.json#L863)的声明上限均为 4096 | A/B 冻结进入当前 binding 的 2001–4096 请求如何准入/拒绝，C 依明确映射消费；不得静默截断或据较宽 schema 宣称引擎支持 |

## 4. 验证、证据与交付方式

每个单元先固定写入文件、接口输入输出、行为断言与依赖；逻辑修复先观察反例，再做最小修复及必要回归。符号与调用定位按 `codebase-memory` 核对覆盖；工具/索引不可用时直接读源码并说明限制。具体实施按对应技能和[验证指南](../agent-verification.md)，冻结字段前不把阶段计划当成已完成接口设计。

| 改动或证据 | 验证入口及判定 |
| --- | --- |
| 规划和索引 | 本地链接、frontmatter、命令及事实范围，`git diff --check`；不安装依赖或运行业务测试 |
| 操作/验收映射 | `make operation-coverage-check`；显式设置 `ACCEPTANCE_EVIDENCE_ROOT` 后运行 `make acceptance-map-check`，并人工审查语义。已知缺口返回非零时保留失败，不放宽守卫 |
| Python/Web | 受影响的 Ruff、mypy、依赖边界与 pytest；Web format/lint/typecheck/test/build，适用时加真实浏览器。复用仍有效证据，不无条件重复全量测试 |
| 契约与生成 | canonical 源、生成类型、样例和消费者同步；`make contracts-check`、`make contracts-drift`、相关契约测试及适用兼容检查，基线用本单元已核实 SHA |
| 持久化/恢复/协调 | 相关隔离 PG/MinIO 和实际提交后丢回执/并发/重启用例；涉及协调、DDL/权限时按规则运行双库协调与集成检查，先读目标目录规则及宿主前置 |
| 模型/设备/部署资格 | 分别记录真实公开服务、真实模型、物理设备和目标拓扑；合成输入、fixture、跳过或健康检查不升级为其他层资格 |

证据原件保存到仓库外稳定根 `/Users/hrygo/.codex/team-c-evidence/<YYYY-MM-DDTHHMMSS+0800>/`，每根有 `manifest.json`；共享结论放入 `docs/audits/`。交接至少包含：

- 任务/原 AC 子条件、生产者/消费者、共同 SHA 与 head、契约/生成器和适用镜像/模型/声音修订。
- 命令、样例来源、环境/拓扑/浏览器/设备、事前阈值、实际结果、原件路径及摘要。
- 已实现、已集成、已验证、已验收分别说明；失败、跳过、未知和具名依赖保留原状态。
- 原身份及幂等键的脱敏对应、执行/发布/对象副作用与停止/资源账目；不记录凭据值或完整业务正文。

清理工作树前核对被忽略内容并确认原件已在稳定根；新组合只重验受影响范围，旧版本实验不自动升级为新版本证据。每个单元收尾向用户报告实际交付、证据及限制、待接收制品与下一步；仅文档落盘不触发实现、模型实验或远端状态变更。

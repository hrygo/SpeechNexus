# 合并后同步 Issues

常规目标是一个 PR 完整解决并关闭一个小 issue；有剩余范围或跨项影响时，再同步相应进展和依赖。关闭仍须有完整交付与 AC 证据。

## 入口与范围

在已授权的 PR 合并收尾，或用户明确要求同步已合并 PR 的相关 issue 时执行；授权已覆盖的正文、state 与标签维护直接完成。查询、审查或建议请求只交付核对结果和拟改内容。

本技能不授权合并其他 PR、调整需求/AC、创建 issue/标签、修改负责人/关系、发布或业务运行态变更；也不安装 Action、webhook 或定时任务。范围外事项先保留为建议，继续已授权部分。

使用当前可用的 GitHub 连接器，能力不足时使用已认证的原生 `gh`；不读取令牌或新建鉴权配置。访问失败则报告未完成项。

## 默认路径：一个 PR 关闭一个小 issue

- 从直接关联的 issue 开始，核对该 PR 是否完成其完整范围、任务与 AC。已授权起草/编辑 PR 且计划完整解决该 issue 时，可用 `Closes #N` / `Fixes #N` 表达关闭意图；关键字不替代验收证据。
- 合入主干且上述条件满足后，直接维护为 `closed` / `completed` 与 `status:done`，不强制经过 `integration`、`qualification` 等中间状态。复用适用于已合入内容的有效证据，不给小 issue 增加原 AC 未要求的阶段或资格门槛。
- GitHub 已正确自动关闭时保留关闭结果，只补必要的正文或状态标签；正文、勾选、状态和标签已准确则核对后结束，不重新开关、不追加重复评论。
- 没有实际父项、Gate、依赖方或编排关联时，同步范围止于这一个 issue，不扫描总控或刷新跟踪矩阵。确有部分交付、多 PR、跨项影响或剩余 AC 时，才展开下述对应分支。

## 按需材料

- 编辑正文前读[共同正文规范](../speechnexus-issue-maintenance/references/issue-body.md)：四部分、任务/AC、层级、证据与长度预算的唯一维护入口。
- 判定 AC、state、关闭/重开或标签时读[状态与证据](references/status-and-evidence.md)。
- 确认涉及实施编排的父项、Gate 或依赖制品后，再读[编排与快照](references/delivery-tracker.md)。不默认加载整份团队计划。

## 1. 核实主干集成与直接影响

核对目标仓库、PR 和远端默认分支或明确指定的主干，确认 PR 实际合入该主干，记录 URL、base、合并时间及集成 commit；不从当前本地分支猜主干。未合并、仅关闭或合入其他分支时，不执行完成更新。

读取 PR 正文、实际 diff、必要审查与检查，核对 revision、环境、结果与覆盖限制，检查后续回退或证据失效。从原生关联、closing references 和明确交付引用建立候选集；`Closes`/`Fixes` 只是线索。背景提及、同名匹配不构成写入目标，跨仓库目标须另核授权。

读取直接相关 issue 最新正文、state/关闭原因、标签、必要关系字段与证据。只有关系确实存在且本次交付影响其内容时，才定位父 Epic、Gate、总控或依赖方；普通独立 issue 到此收敛范围。

## 2. 分别判断交付、验收和状态

按状态参考，为每张确认相关的 issue 固定以下事实，可保留在上下文中：关联依据；本次交付与对应任务/AC 证据；剩余实现、接入、资格或真正阻塞；拟改正文和当前→目标状态。

逐项核对任务与 AC，不按完成比例或 CI 颜色批量勾选。混合要求只完成部分时保留未勾选并说明剩余范围；完整要求、阈值和失败路径不变。仅同步时缺证据就保留待验证，不扩成业务实施。

工作包按完整范围关闭，Gate、Epic 和总控按各自前置与退出条件判断。closing keyword 误关仅在核实事件和证据、授权覆盖状态维护时纠正；其他原因不明的关闭先报告建议。

## 3. 维护当前正文并安全写入

按共同正文规范就地替换、合并和去重，执行长度与增长检查；保留未完成要求、当前失败、风险、阻塞与唯一证据。不新增逐轮章节、折叠日志或重复长评论；无事实变化就不写入。

1. 固定本次拟改字段。仅正文模式保持 state 与元数据；完整同步按已核实结果维护 state 和唯一现有 `status:*` 标签。
2. 每次写前即时重读正文、state、标签与更新时间。保留并行新内容；同段意图不明则暂停该 issue，继续其他项。能安全合并时刷新重算一次，仍冲突则报告，不用旧全文覆盖。
3. 只改计划内字段，保留标题、非状态标签、负责人、里程碑、优先级、Projects 字段和原生关系。接口要求全量标签时，以最新集合仅替换 `status:*`；Projects 只有授权覆盖且已核对真实字段/选项时才写。
4. 优先结构化更新；`gh` 多行正文写临时 UTF-8 文件并用 `--body-file`。允许时一次更新相关字段，分步时先写证据正文，关闭最后执行。
5. 写后回读四部分、要求、任务/AC 勾选、依赖、长度、state/关闭原因及唯一状态标签，确认未授权字段保持。超时或结果未知先查现状，再补缺失步骤；权限错误或持续冲突时停止该项并报告，不盲目重放。

## 4. 快照与交付

确认涉及当前编排时，按快照参考刷新本地矩阵，先保留已有 diff；刷新失败只报告快照未更新，不回退已核实的远端结果。不因刷新自动提交、推送或建 PR。

最终给出 PR 合并依据、每张相关 issue 链接、state/标签和正文/任务/AC 的变化及剩余工作；区分写后已回读、无需变更、未写入/失败。没有确认相关项时说明检索范围；只演练时明确改动均为建议。

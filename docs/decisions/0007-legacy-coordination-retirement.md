# ADR 0007 遗留协调原型的退出与删除

## 背景

[ADR 0006](0006-cluster-coordination-and-storage-portability.md) 已将跨表协调规则的
主要执行边界迁入受控应用事务。旧 PostgreSQL 函数、触发器与独立 SQL 拦截测试
暂时保留为规则迁移的对照证据，不是目标产品实现。

当前旧草案没有已部署业务运行态，无需承担旧生产版本的长期兼容维护。
持续运行旧原型只能验证旧机制，不能补足新实现的行为或故障恢复证据。
用户已确认：遗留设计应在适当时机退出和删除，不形成永久 CI 或维护负担。

## 决定

1. **当前架构的行为验证持续保留。** PostgreSQL / MySQL-InnoDB 共享事务测试
   继续验证已约定的协调语义；数据库支持范围、集群要求及未验证项仍遵循 ADR 0006。
2. **遗留原型仅过渡保留。** 旧 PG 回归、SQL fixture 与长篇旧设计有明确退出条件；
   不因历史审查曾要求保留，就无限期维持每次 PR 的必跑门禁。
3. **迁移业务要求，退役旧机制。** 预算不可超卖、原子性、幂等、fencing、
   停止证据、历史保护和最小权限等仍有效的要求进入新路径测试。
   仅验证旧函数、触发器、调用来源或数据库独立拦截能力的用例，按已接受的
   保护边界变化退役，不要求新架构复刻旧机制。
4. **满足条件后完成清理。** 从默认 CI 和本机验证入口移除旧测试，并从工作树
   删除无当前用途的旧测试、SQL、设计与专属辅助逻辑。Git 历史保留可追溯证据；
   当前文档只保留简明决定、规则映射与必要的历史定位信息。

## 退出条件与复核时机

每次接入新的协调事务行为或补齐旧规则覆盖时，由该变更的实施者复核下列条件，
在变更说明中记录结果；全部满足后，在同一变更或紧随其后的清理变更中执行退出。
不以等待全产品实现或全部 P5 资格为由无限延期。

- 旧用例已逐项分类：仍有效的业务不变量有新执行位置及对应测试；
  旧机制专属保证有 ADR 0006 的明确替代依据，没有未归类或静默丢弃的负例。
- 仍有效的不变量在新路径有可执行正负例；涉及竞争、回滚和未知结果恢复的
  相关场景已在隔离 PG/InnoDB 上验证。缺失项先补齐，不能用旧测试通过替代。
- 生产代码、活动 DDL 和当前验证入口不依赖旧 SQL、旧测试或旧设计来运行或判定正确性；
  对这些文件的静态读取、函数计数和历史映射断言已清点，随清理移除或改验当前事实。
- 清理变更记录最后可复现旧原型的 Git 提交与路径，更新有效文档和命令入口，
  并使当前架构的契约、共享事务及相关权限测试继续通过。

尚未实现的生命周期和集群资格继续在实施计划中明确追踪；删除旧原型不能把它们
标成已实现或已验证。若其中包含尚未迁移的旧业务不变量，先完成该项迁移验证。

## 清理范围与保留边界

清理对象包括 `tests/integration/test_cluster_coordination_schema.py`、
`tests/fixtures/coordination/legacy_postgresql.sql`、
`docs/architecture/legacy-postgresql-coordination.md`，以及只服务这些文件的
契约断言、fixture/helper、CI 步骤内容、命令与导航链接。共享测试文件中的当前
协议检查必须保留，不得整文件误删。

ADR、简明规则映射及历史审查的原时点事实继续可追溯；无需在工作树长期保存一套
可执行的废弃架构，也无需为此另建永久定时 CI。
本决定针对仓库原型文件，不授权删除运行数据库中的执行、计量、租约、fencing
或删除账本等证据。

## 当前执行状态

本次记录退出决定与条件，尚未完成逐项迁移验收，未停用 CI 或删除旧文件。
具体复核与清理跟随[集群协调重构计划](../plans/2026-10-23-cluster-coordination-refactor.md)。
本决定替代该计划及活动文档中可被理解为永久保留旧原型的要求，不改变其历史验证事实。

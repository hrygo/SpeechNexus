# SpeechNexus 团队 A 执行目标

## 目标

作为云开发环境中的团队 A，按照[三团队实施方案](2026-10-23-three-team-delivery-plan.md)和[总控 #6](https://github.com/hrygo/SpeechNexus/issues/6)，交付 A00–A07 范围内的平台、协调、数据、公开 API 与发布恢复能力；向 B/C 提供版本明确、可验证的接口与证据，支撑整体产品通过对应 G0–G5。目标从规划 PR 合并后的 `main` 启动，不把当前已创建的 Issue、契约或测试原型当作业务已实现。

本文件是可执行目标定义，不证明应用原生 Goal 已启用。原生 Goal 的启用状态以 Codex 应用或目标工具返回结果为准。

## 后续路线与边界

按具名制品依赖推进 A02/A03/A04 的文件闭环，再推进 A05/A06 的实时与音色，A07 的删除、恢复及交付检查从首个资源开始持续加入。A01 的 18 端口总验收按所有权汇总：A 实现 speech/runtime，B 实现 gateway，不能为了进度共写对方权威表。

公共文件、迁移顺序和集成由 A 排队维护。只认明确的停止/释放事实，不以取消、TTL 或断线退预算；工作台仅使用公开语音协议；LLM 默认关闭且只用批准内网；业务内容不出网。

每个任务在获得当前会话 Git 授权时使用短分支/PR 交付；合并需满足保护规则和必需检查。未授权的部署、GPU/模型、生产数据或第三方运行态不因目标持续执行而自动获得授权。

## 完成与阻塞条件

团队 A 的范围只有在 A00–A07 对应子任务、生产消费者与必要真实资格全部完成，并提供可追溯证据后才算完成。G0–G5 由三队联合取证、总指挥决定放行；A 端交付完成不等于其他团队或全项目完成，不能越权关闭 Gate。

缺少 B/C 的具名输入、必要环境或关键产品决定时，继续不依赖该输入的任务；依赖工作明确标为待联调或阻塞，报告所缺制品、owner 和解除条件。不能用虚构模型/接口、fake 或原型替代真实验收，也不在无可继续任务时无限重复检查。

每项任务开工前，先更新 A 自己负责的 Issue 的唯一状态标签、正文任务清单、当前单元、依赖与验收标准，再开始实施；交付后按证据勾选、刷新矩阵并提供下一轮建议。历史 Issue 同样按实际交付补齐状态，C 的 Issue 由 C 维护；不因 PR 合并自动关闭整个父工作包。

矩阵刷新后若只有快照检查时间/读取方式变化，表内状态、依赖和证据内容均未变，实现 PR 不提交这类时间戳差异；在相关 A Issue/总控记录核对与当前单元。实际状态/依赖/证据变化必须更新矩阵，避免三个团队的无关时间戳冲突反复触发 CI。

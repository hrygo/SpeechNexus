# 项目经理工作约定

适用于项目统筹、接管、跨团队排期与阶段验收。所有团队共同遵循[根工作约定](../AGENTS.md)；本页补充项目经理的工作方法，不扩大提交、合并、派工、消息、部署或数据操作的授权。

## 工作入口与事实来源

接管或新会话开始项目管理工作时，按以下顺序建立上下文：

1. 读[项目经理接管基线](plans/2026-10-26-project-manager-baseline.md)，了解产品边界、已有能力、缺口、历史风险和证据位置。
2. 核对[总控 #6](https://github.com/hrygo/SpeechNexus/issues/6)及本次相关 issue，确认当前优先级、负责人、依赖、剩余范围和 AC。
3. 核对相关 PR、远端目标分支、契约、源码与实际证据，固定本次集成版本和验证范围。

基线是有日期的接管快照，会话历史提供检索线索。持续工作只补读相关变化；全面盘点时再覆盖全部跟踪项，不为每个局部任务重复扫描全项目。

当前实现与实测结果、有效契约与设计预期分别记录。发现冲突时保留具体差异、影响与待决事项；不凭历史测试数、目录存在或口头交接认定当前能力已交付。

## 排期与协作

- 用 #6 维护当前组合、近期队列和跨团队依赖；人员、机器、模型和窗口以当前任务中的明确安排为准，旧团队名称与排期不自动续作。
- 按可独立验收的小交付组织 issue/PR，明确目标、范围、AC、实施与审查归属、输入、输出和验证条件。简单任务直接执行，不默认拆成多份计划或要求所有团队会签。
- 跨模块任务明确提供者、消费者和共享文件的唯一写入归属；共享契约、生成产物、迁移和公共文档由约定的维护者串行接入。
- 依赖以具名接口、固定制品、样例、迁移、binding 或环境为单位。必要输入缺失时写明提供方、解除条件和可继续的独立工作，不默认等待关联整包关闭。

职责按模块边界划分，实际团队与人员在任务中确认：

| 职责范围 | 主要交付与协作边界 |
| --- | --- |
| 语音底座与平台 | 机器契约、权威配置/状态、Job/准入/预算、迁移和公开发布；向执行层与正式消费者交固定输入和公开结果 |
| 执行与部署 | 引擎、网关、控制器、固定执行制品及可信停止/释放证据；由底座原事务处理权威结算 |
| 正式消费者与工作台 | SDK/页面接入、工作台自有状态、业务编排和设备体验；经公开语音协议消费底座 |
| 项目统筹与集成 | 优先级、输入与窗口、共享改动协调、审查/验收、主干集成、进度和交接；按已有授权组织实施 |

提供者交付源码/镜像/模型/契约 revision、输入/输出摘要、环境拓扑、实际结果及失败/未验证项，消费者回执实际接入结果。平台自测不代签执行兼容性，私有执行不代签公开发布，页面通过不代签公开生产者；凭据使用批准配置链，不写入交接材料。

## 验证、集成与验收

1. 合并前固定精确 head，审阅最终 diff、兼容边界和适用检查。失败修复后复验，确认修复包含在最终提交中。
2. 合并后核实远端目标主干的实际提交与检查，区分 PR 检查、合后检查和仍有效的历史证据；不从本地分支猜测集成状态。
3. 分开记录实现、生产接线、行为验证和运行资格。fake、合成媒体、双库分片、真实引擎、浏览器/设备与物理拓扑各自只证明覆盖范围；跳过和未运行单列。
4. 任务完成与 AC 勾选分开判断；完整工作包按全部范围关闭，Gate 保留前置、联合证据和既定用户放行要求。CI 绿灯不代替业务或目标拓扑验收。

检查范围与宿主前置统一使用[验证指南](agent-verification.md)和[CI 规则](architecture/ci-validation.md)。复用仍有效证据，仅在改动、失败或未解疑点需要时扩大验证；CI 耗时优化须测量，不通过削减双库/业务检查或放宽校验达到目标。原失败按原版本保留，不被后来成功覆盖。

## 进度与文档维护

- issue 正文保留当前目标、进展、任务和 AC，就地替换、合并、去重，保留有效唯一证据；外部反馈保留报告者的问题和复现。详细实验放固定证据，不逐轮追加正文或重复长评论。
- 写前重读最新正文和必要元数据；发生并行修改时保留新内容，同段意图不明则暂停该项。仅正文修改保留元数据，状态同步限于本次授权覆盖的字段，写后回读核验。
- 合并收尾按[合并后同步](../.agents/skills/sync-issues-after-merge/SKILL.md)维护直接关联项；只有确实受到影响的父项、Gate 或依赖方才扩展同步。需要刷新跟踪矩阵时核对其来源与时间，避免维护另一套独立进度。
- 长期规则维护在本页；当前组合、优先级和依赖维护在 #6 及对应 issue；基线保存接管时点事实和风险，历史计划/审查记录保留原时点结论。需要改变架构或公共协议时按对应技能更新有效文档及 ADR。

Issue 格式、状态与关闭细则以[贡献指南](../CONTRIBUTING.md)和对应技能为准，本页不另设状态体系。

## 证据、清理与交接

- 证据放在工作树外，记录固定版本、命令、环境、结果与覆盖限制。作者报告、接收方已取得原件、接收方已按 manifest 核验分别标注；重建证据不冒充遗失原件找回。
- 清理前保存所需补丁、refs/bundle、未提交/未跟踪文件和必要忽略文件，并核验可恢复性。Git bundle 只保护已进入 Git 的对象与引用，不能代替工作区和运行数据备份。
- 只清理本次授权覆盖、已结束且无活动引用的 worktree/分支；使用适用的应用归档流程。其他任务、未知改动、固定保护、模型、运行数据和服务分别核对，无法确认时保留并说明条件。
- 阶段交接说明实际集成版本、已实现/已验证/未验证、未结风险、下一项交付及所需负责人/输入/窗口，并链接当前 issue 和证据。文档完成不自动启动部署、GPU 实验或下一轮实施。

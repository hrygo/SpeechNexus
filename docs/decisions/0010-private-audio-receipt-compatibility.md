# ADR 0010 私有音频回执与旧 JSON 消费者兼容

## 背景

原 `ExecutionStagingResult` 是 closed JSON 回执，媒体固定 `application/json`，
正文上限 4 MiB。把媒体枚举和音频字段直接加入旧响应，会破坏已部署的严格消费者。
现有源 PCM 账本只保存不可变区间与 max-end 水位；水位不等于实际生成区间总长度。
音频结果不能绕过该账本，也不应建立另一份计量或结果权威。

## 决定

保留旧 JSON 类型和 `GET .../staging-result` 路径的形状与约束。
新增 `ExecutionAudioStagingResult` 和独立 `GET .../audio-staging-result`，
复用组件认证、原执行身份、节点/网关范围及同一 `submit_intents` 回执列。
协调观察请求新增独立的可选属性 `audio_staging_result`，而不是把原
`staging_result` 改成 `oneOf`：只加可选属性时旧属性的形状与约束逐字不变，
两个属性同时出现按无效请求拒绝。该结构变更门禁要求对请求方向的组合重排
单独取证，本次采用加法形式即可通过，无需放宽任何校验。
旧路径对音频记录返回 null，新路径对 JSON 记录返回 null；两者的 null 均不证明
无对象、无计算或可重派发。通用状态仍只投影原有六字段引用。

首个持久音频范围是 24 kHz、单声道 PCM16LE，交付 WAV/PCM/MP3，
源 PCM 与编码载荷各最多 64 MiB。回执记录固定对象版本、长度、摘要及源 PCM
样本数/摘要/时长；MP3 padding 不改变源时钟。PCM 载荷长度与摘要必须等于源 PCM。
生成类型只证明形状；领域边界另验时长公式、容器与样本一致性。

首次登记仍经原观察事务与 CAS，在原 submit 锁内检查既有生成区间：
必须完整覆盖 `[0, source_pcm_samples)`、无缺口，且匹配原输出流、采样率、
水位和冻结上界。区间端口已保证不重叠，登记只读其 min/max/sum，不新增计数投影。
同键确认丢失查原身份；精确回执在当前版本重放保持只读，包括后来的取消/停止。
结果登记不签发终态、停止或资源释放，不修改 A 预算。

ASR/TTS 共用固定私有 S3 origin、一次 PUT、版本 HEAD/GET 和摘要读回机制；
各自保留领域类型、格式、上界及稳定错误。操作具有独立客户端与累计期限，
失败不自动重试、发布、删除或再次推理。

## 升级与回退

HTTP 旧消费者保持 JSON view，不接收未知音频字段。数据库格式兼容需单独处理：
旧进程只认识 JSON，不能读取新音频回执。因此先升级所有相关 ledger 读取者和
接收方，再启用任何持久 TTS 生产者。没有消费者能力确认时保持 TTS 未启用，
不能凭同一集群正在滚动升级推断安全。

不新增 DDL、表或写入权限。旧 JSON 文档仍由原严格解析器读取，新音频由独立严格
解析器读取；损坏、重复键、非规范文档和未知字段均拒绝，不根据 key 补造回执。
本变更提供合成器→编码→私有 staging→原区间/回执登记→鉴权查询的组件接线；
生产 TTS command/default factory、A 发布及公开下载仍须单独交付与验收。

停用新 TTS 生产者可以回退启用状态；一旦已有音频历史，读取进程须保留新解析器。
不能通过清空回执或降级旧读取者实现回退，不将原记录当作可重跑队列。

## 验证边界

比较旧路径与严格响应的结构兼容，运行共享 Python/TS 正负例、领域语义反例，
以及隔离 PG/InnoDB/MinIO 的登记、竞争、回滚和原身份恢复。合成引擎与真实编码、
存储不证明真实模型、公开消费链、停止/释放或物理集群资格。

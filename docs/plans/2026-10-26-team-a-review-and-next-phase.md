## 关键判断与改进方向

1. **主要短板已转向生产装配。** 原键、完整命令、锁后取时、单事务预算、最小权限和 unknown 保护继续复用。
   再新增同类包装或草稿存储，不能自动解除 C 的公开 Job 阻塞。
2. **配置声明与执行许可之间缺权威事实链。** 显式默认快照、#139 观察边界、#172 原意图账本，
   都不是可信校验生产者、发布指针或最终参数许可。
   首条 ASR 可不带 Profile，但必须有固定、可信、可用的绑定和有效参数。
3. **输入和输出两端都未闭合。** 当前 AssetRuntime 仍装配 TextAssetInspector；
   B 私有持久回执已有，A 的 Artifact/Operation/公开成功事实仍缺。
   不把“对象存在”或“收到回执”当成功、停止或预算释放。
4. **状态维护落后影响派工。** #141/#155/#201 和 C 集成事实已改变，旧目标与部分 issue 尚未同步。
   每次只更新受影响的任务/AC，分清候选、合前、合后与联合验收。
5. **交付节奏围绕依赖解除。** 共享源、生成器、锁、迁移和组合根串行；一次一个主要写入单元。
   按“本轮新增哪个真实消费者、解除谁的哪个阻塞”选工作，PR/测试/清理数量不代替产品收益。

M1 是下一个主要实施单元，M0 的只读核对先行。
首个工程动作是冻结独立 media kernel/inspection entrypoint 与构建来源，
不是把整个 gateway wheel 导入 backend 或复制 decoder。
公共错误/媒体投影先改源契约；raw PCM 缺格式元数据时不从裸字节推断。

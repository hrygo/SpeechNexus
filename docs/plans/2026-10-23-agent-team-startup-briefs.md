# SpeechNexus agent 三团队首轮派工

配合[整体实施计划](2026-10-23-three-team-delivery-plan.md)使用。用户统一指挥三个 Codex 团队，A 在云环境、B 在 MegaCube、C 在 MacBook。以下是首轮可直接下发的任务文本；本文件没有启动这些任务，也没有建立其他机器连接。

远端派工入口为 [总控 #6](https://github.com/hrygo/SpeechNexus/issues/6)。首轮三张主卡分别对应 [A00 #19](https://github.com/hrygo/SpeechNexus/issues/19)、[B00 #27](https://github.com/hrygo/SpeechNexus/issues/27)、[C00 #35](https://github.com/hrygo/SpeechNexus/issues/35)；本文件提到的 A01/B01/B02/C01/C02/C04 仅提前分派其具名子单元，不等于整个父工作包已可真实联调或已实施。G0 在 [#13](https://github.com/hrygo/SpeechNexus/issues/13)集中取证，状态与依赖见[跟踪矩阵](2026-10-23-implementation-tracking.md)。

## 1. 总指挥启动卡

先把计划及本轮公共材料同步到各队可读的位置，再将同一个 `integration_base_sha` 交给三队。`390f121` 是计划的代码事实基准，实施应从指挥者确认的集成版本启动，不应永久固定旧 SHA。

```text
共同目标：完成 S0/G0，为第一条“文件转写→持久 Job→校对/下载”闭环准备可消费接口、风险证据和 fake。
集成基线：<integration_base_sha>
团队：A 云环境 / B MegaCube GPU / C MacBook
单次任务：先完成本卡范围，交付后等待下一张任务卡，不自行扩展后续业务。
Git：按本轮明确授权提交/推送；没有授权则保留本地改动并交包含新增文件的补丁和基线/校验值。
运行态：只执行本卡明确批准的探针/测试；先检查现有状态，不覆盖凭据、模型、服务或用户改动。
统一汇报：基线/产物版本、可写路径、实现/验证事实、结果与未验证项、阻塞、交给下一队的接口。
```

每轮收三份交接包，交给 A 做代码与证据整合。总指挥只需裁决接口/范围冲突、运行态授权和关口放行；字段与样例的核对由生产者、消费者自行完成。只有已授权的 Git 操作才可执行，避免为了跨环境同步隐含扩大权限。

## 2. A 队：云端平台与协调

可下发任务：

> 你是 SpeechNexus A 队，负责平台与协调，使用本卡指定的集成基线。阅读仓库 AGENTS.md、三团队整体计划、协调事务方案和最新架构审查。先核对分支、HEAD、已有改动和云环境能力；追踪结构先查询 CBM 并检查覆盖，缺失时读源码。保留并行改动。
>
> 本轮只做 A00 与 A01 的首个验收单元：一份 18 端口/表/契约/消费者责任矩阵；锁定并建立最小 Python/TS 类型生成/校验流水线与漂移检查，先交付首闭环所需接口和样例；定义全配方 admission、Job/outbox、网关 intent 和查询快照的边界；实现一个可独立验证的生产 PG 事务与版本化迁移/最小角色骨架。其余端口只给出明确的后续子任务，不一次实现整个底座。
>
> A 独占生成器与共享 schema 的维护。B/C 可以消费生成产物并反馈问题，不能各写一套默认值。接口/样例子包完成即先交接，让消费者继续；不要等本轮全部工作结束才交付。18 个端口现有契约不等于已实现；优先列明四个无行为原型端口及完整 `value` 快照缺口。
>
> 范围为 speech/domain/application/infrastructure 的相关小单元、生成工具、必要迁移/权限和针对性测试。网关内部实现、工作台业务和页面不在本轮写入范围；共享组合根/锁文件/CI 改动由你统一排队集成，保留其他团队需求。
>
> 不导入 tests/support 作为产品依赖，不引入 etcd 或通用分布式事务系统，不把 admission 拆成多次独立提交。数据库规则、锁序、数据库取时、已回滚才重试与 unknown 查原身份需要真实证据；相关协调变更在隔离 PG/InnoDB 上执行同一行为测试，两库无跳过。缺少环境时报告阻塞，不用 fake 冒充双库通过。
>
> 交付接口子包/生成版本、首个生产事务与测试结果、文件闭环所需端口清单、剩余缺口、B/C 的接入样例和下一张 A01/A02/A03 任务卡。首轮不加载模型，不改 MegaCube 运行态，不宣称 G1 完成。

首轮验收：B/C 能验证同一组合法/非法请求；存在真实生产代码和迁移单元；测试结果区分实际通过、跳过和环境阻塞；没有把测试原型移入组合根。首个生产事务具体选型在 A 的任务卡中说明，例如 `create_job` 的同键重放/异摘要冲突/Job+outbox 同事务。

## 3. B 队：MegaCube 执行与模型

可下发任务：

> 你是 SpeechNexus B 队，负责执行网关、引擎和受限控制器，工作在 MegaCube 上。以指定集成基线核对仓库/AGENTS.md、ADR0002/0004/0006、内部执行与运行时协议。先只读检查 OS/CPU/GPU/内存/驱动/CUDA、容器/磁盘、已安装制品、现有进程/端口和资源占用；不从机器名称推断资格，不改变已有服务或凭据。
>
> 本轮做 B00 与 B01/B02 的最小准备。先交一份真实环境与能力缺口矩阵：文件 ASR、TTS、实时、VoiceDesign/Base 的候选版本、输入输出、request ID、status/abort、强输出上界、停止/资源事实与峰值。调查可并行，实际 GPU 实验由你统一排队。只在本轮明确获准的环境/制品/合成或授权语料上运行探针；没有许可或制品时报告缺口并继续独立 fake，不自动下载模型、改驱动、停服务或扩大暴露端口。
>
> 同时建立可供 A 消费的 fake engine/controller 故障场景，以及网关持久 submit intent、完整规范命令、重复提交、unknown 查询、停止观察和 generation 的接口实现草图。实际实现先取一个闭合单元，如“持久唯一 intent + 同键重放不再次 dispatch”；与 A 的生产迁移/租约查询对接，不能另建一套预算权威。
>
> A 发布接口子包后固定版本消费。只在 execution-gateway 和你负责的 fake/adapter/测试范围写入；controller 新包/迁移/deploy/锁文件变化先交 A 排队集成。你不写工作台业务，不替 Scheduler 释放预算，不把 HTTP 断开、取消已接收或 TTL 当停止证据。
>
> 交付环境事实、探针实测与未验证项、模型/镜像/许可清单和 manifest 草案、fake 故障接口包、网关首个单元与测试、GPU 当前状态/清理结果。单 MegaCube 的多进程只标逻辑集群；不能宣称多算力主机接管已通过。给出下一张 B01/B02/B03 任务卡。

首轮验收：A 能消费停止/unknown/迟到结果场景；真实探针有模型/镜像/硬件和可重复步骤；缺失 stop、输出上界或资格的路径明确受限；现有 GPU 服务未被破坏。

## 4. C 队：MacBook 工作台与体验

可下发任务：

> 你是 SpeechNexus C 队，负责 workbench 后端、两个 Web 入口、浏览器媒体和业务体验，使用指定集成基线。阅读 AGENTS.md、三团队计划、Web 设计框架、speech/admin/workbench 契约与实时事件。先检查仓库状态、Node/Python 工具链、浏览器与本机能力；不运行仅适用 Linux 的服务管理脚本。
>
> 本轮做 C00、C01/C02 的最小 fake 业务切片与 C04 独立媒体探针。先核对项目/校对 revision、转写文本/字幕导出协议是否满足首闭环；缺少契约时反馈给维护者，不私造接口。A 独占生成流水线，你消费已发布类型/客户端/事件 validator；等待接口时可做页面状态与共享组件，不能手写另一套字段/默认值。
>
> 页面实现最小 Admin 能力/任务视图和工作台“上传→任务详情→校对→下载”交互，覆盖取消未知、失败/冲突、重放、SSE 重连、历史过期重读与 Artifact 过期。fake 仅在明确开发模式启用，不进入真实遥测，能力状态保持 contract/planned，不能把假链路标 ready，也不增加 mock 能力枚举。不要本轮扩展完整会议/助手/有声书。
>
> 媒体先用合成 PCM/fake WS 验证 AudioWorklet、有界缓冲/时钟、credit/gap/epoch、播放 generation 和停止/卸载清理；PCM 不放 React 查询缓存，迟到旧音频要丢弃。真实麦克风/屏幕音频、浏览器 UI 操作和远端 GPU 联调按具体授权与支持矩阵另验，不假定都已通过。
>
> workbench 独立 schema、对象区和版本用例可以先实现一个小单元；不得导入 speech 内部模块、共写底座表或直接访问引擎。模块迁移/deploy/公共锁文件通过 A 集成。web/shared 同一文件只设一个 agent 写入者。
>
> 对改动运行适用的 Web 格式/lint/类型/测试/构建，报告实际结果。交付页面/fake 场景、消费的契约版本、工作台版本与导出缺口、媒体探针结果、真实浏览器/设备尚未验证项，以及下一张 C01/C02/C04 任务卡。Linux 服务/镜像结果和 Mac 浏览器结果分开报告。

首轮验收：界面准确呈现待实现/未知状态；具备可重复的 fake 故障流程；客户端与 A 的同版本样例一致；合成媒体、实际设备和 GPU 联调证据分层。Mac 浏览器访问远端使用批准的 HTTPS/WSS/同源入口和 Host/Origin，不把数据库、内部引擎地址或组件凭据发给浏览器。

## 5. 每轮交接包与 G0 判定

各队按同一模板汇报：

```text
团队/任务 ID：
base_sha / head_sha；或补丁文件与校验值：
修改范围与契约/生成器版本：
可交给下一队的接口、样例和制品：
验证命令/环境/结果；未验证与阻塞：
运行态变更及清理结果：
下一队的接入动作；下一任务建议：
```

A 收敛为“本轮集成 SHA、三队结果、关键阻塞、G0 是否满足、下一轮三张卡”。G0 未通过时只补阻塞单元，已经通过的独立部分不重复重做。第一轮交接不是产品发布；G0 之后才接第一条真实文件闭环，后续任务编号沿用主计划，不重编号 C04 媒体或其他父包。

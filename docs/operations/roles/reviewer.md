# 交叉评审

对明确委派的方案或固定候选做独立反证。本角色保持只读，不修改作者代码或原始报告。

> 本页是派工简报；与[共用边界](common.md)一起用于独立审查会话或 subagent，不构成平台岗位、模型配置或权限。审查独立性按是否参与实现及是否具备独立上下文判断。

## 评审范围

- 取得原验收条件、候选版本和已有证据，沿源码核对身份、版本、调用链、时序、恢复与资源释放；只扩大与当前风险有关的范围。
- 使用宿主授予的读取和搜索工具。完整 HEAD / hash 由任务或宿主提供；不为报告格式调用 Bash、安装依赖、运行测试或写 JSON。需要实跑时交具备环境与授权的执行者取证。
- 每项发现给严重度、精确位置、触发条件、影响、证据和最小修正建议。无发现时如实列已读 / 仅扫描 / 未验范围；搜索未命中不证明实现不存在。

## 评审交付

把审查结论交回派发方（issue 评论、PR 审查或报告），包含受检版本、依据和限制，不假称完成未提供的状态变更。本人参与实施或接入修改的候选不得独审；高风险改变仍需合格非作者与对应环境验证，不由角色名或模型名推定资格。未受委派时不增加常设评审层。

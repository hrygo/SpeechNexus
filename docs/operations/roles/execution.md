# 执行与 GPU

负责执行网关、节点控制器、执行身份与媒体限额，以及可信停止 / 释放、Linux aarch64 和真实 GPU 验证。

> 本页是派工简报；与[共用边界](common.md)一起用于 subagent、独立会话或 Linux GPU 主机上的 GPU Agent，不构成平台岗位、模型配置或权限。

## 执行边界

- 从当前任务取得批准的镜像、模型、instance / generation、隔离数据库 / 对象存储及秘密引用，使用已验证的工具链与回传路径，不沿用历史端点或擅换传输模式。
- 区分请求、binding、实际 policy 和媒体各层限额。提交未知时按原身份查询或恢复；取消接受、逻辑结束、进程退出与 TTL 均不单独证明引擎停止和资源释放。
- 向权威事务方交固定版本制品、执行身份及停止 / 释放证据；不自建预算账本、跨模块改表或把私有 staging 当公开发布。
- 重型 CPU 与 GPU 验证使用批准窗口，核共享内存和常驻服务余量；保护现有模型及共享服务，不卸载或改配置腾资源。沿用宿主 HOME / 缓存隔离，不回退用户共享目录。经 Paperclip 委托执行时，任务卡只承载本次执行，结果交回 issue 与派发方。

## 执行交付

按实际能力与授权直接提交、推送并沿原 PR 返修；仅能回传时，向预定集成写者交完整 base、patch、新文件及必要摘要清单。交实际命令、原始结果和未验项，由接收方取得并核验。区分执行结束、回传、接收与文件收尾；失败保留成果，不重复语音业务或补造提交。可审查本人未参与的契约候选。

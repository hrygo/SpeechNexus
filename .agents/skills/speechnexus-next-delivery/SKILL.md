# 按需规划下一交付

从产品要求、当前实现和依赖中选出下一项可独立验收的工作；只在需要时建卡，不预铺完整 backlog。未建实施 issue 不表示需求遗漏。

## 确定范围与现状

1. 读取 [PRD](../../../docs/prd.md)、[需求与交付矩阵](../../../docs/plans/delivery-tracking.md)及相关设计、契约和当前 GitHub issue；按需读取其[结构化关联源](../../../docs/plans/delivery-issues.json)。以当前代码、生产接线和有效证据核实实现、集成、验证及缺口，分别表述。
2. [总控 #336](https://github.com/hrygo/SpeechNexus/issues/336)之下的十个 Epic（#337–#346）是互斥且完整的产品范围入口；以 PRD 和 Epic 的当前边界确定唯一主归属。跨 Epic 需要协作时关联依赖与具名输入，不为同一工作重复建卡。
3. 找出尚未满足的需求和制约，核实相关 issue、开放 PR 及已交付制品，避免重复派工。选择可验收、边界清晰且输入可取得的切片；必要依赖说明提供者、版本或制品、解除条件和不依赖它的工作。
4. 区分用户已延期的能力和可先推进的共享前置。缺少影响产品范围、公共契约、持久数据或运行边界的决定时，呈现可评审选择并继续独立工作；不凭历史计划自动开启执行。

## 草拟或创建

- 正文以[贡献指南](../../../CONTRIBUTING.md)和[实施模板](../../../.github/ISSUE_TEMPLATE/03-implementation.md)为准，写清背景与目标、范围、可观察验收条件及必要依赖；不为建卡重复设计完整方案。外部反馈保留报告原貌。
- 分析、建议和只读调用只输出候选，不创建或修改远端。已获创建或编辑授权时，直接执行授权内的少量卡片，不重复询问；创建新项目 issue 必须原生直属且仅直属一个对应 Epic，正文提及不能代替父子关系。
- 创建前核对仓库、唯一 Epic、去重结果和本次授权。优先使用支持原生父项的连接器；能力不足时使用已认证的 GitHub CLI。当前 CLI 支持 `gh issue create --repo hrygo/SpeechNexus --parent <Epic编号> --title <标题> --body-file <正文文件>`，使用前核对实际 `--help`；[官方原生关系说明](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues)列有创建和关联命令。无需读取令牌或新建鉴权。
- 创建后读取原生父项核验，不以正文链接或命令退出码单独证明成功。若只能分步创建和关联，沿用原卡身份完成关系；出现非零退出、超时或结果未知时先检索原卡与关系，再决定缺失动作，不重复建卡。关联失败时不得作为就绪任务交付；继续修复，或明确卡片、失败、负责人和解除条件，不留下未说明的游离项。
- 按实际情况对工具、权限或 API 故障有限重试；无法确认事实时停止相关写入并报告，不通过正文链接伪造关系，不擅自关闭或删除卡片。

## 同步与交付

关联经核验后，按授权更新需求矩阵及结构化关联源：需求行保留稳定身份、主 Epic、PRD/设计依据、实现/集成/验证事实和证据；当前实施 issue 可以为空。按仓库现行工具和格式维护，不假定字段或 schema 版本。若关联源或矩阵不可用，报告具体未完成项，不猜测或另建第二份权威清单。

回报候选及选择理由、已确认的需求与父项、已有实现和验证缺口、所需输入、实际创建/关联及矩阵更新结果。区分草稿、已建卡、关系未确认和就绪状态；不因本技能自动设置 Goal、启动 Delegra、创建 worktree 或实施任务。

# v0.1.0 发布制品复核（2026-11-20）

本记录是某个时点的复核证据，不是当前部署说明。

## 结论

`v0.1.0` 的五个镜像 digest 在 `v0.1.0` 标签下仍指向同一批多架构索引，且每个索引都包含 `linux/amd64` 与 `linux/arm64`。**「发布只发 amd64」这一风险已排除。**

**「在独立 arm64 机器上照发布说明部署」本次未验成。**

## 已核验

在构建机上按发布附件钉住的 digest 逐条查询：

```text
$ gh release download v0.1.0 -R hrygo/SpeechNexus
$ shasum -a 256 -c speechnexus-v0.1.0-SHA256SUMS
speechnexus-v0.1.0-images.txt: OK
speechnexus-v0.1.0-compose.yaml: OK
$ docker buildx imagetools inspect ghcr.io/hrygo/speechnexus-<name>@<附件 digest>
```

| 镜像 | 发布附件中的 index digest | 平台 |
| --- | --- | --- |
| `speechnexus-python` | `sha256:2ae77fb44fe3bd064af63b27786c26e8db545115fae5e82b9ba1e1f932fb5514` | `linux/amd64`, `linux/arm64` |
| `speechnexus-web-admin` | `sha256:f5c7dcbaa7e859c66d29f0b303d8830884a809d45a30d03c42efafd37287c3b5` | `linux/amd64`, `linux/arm64` |
| `speechnexus-web-workbench` | `sha256:436e448d004d768f5977368e5d7ec321b4de8b1a0e99bb0bda80859b1af9d957` | `linux/amd64`, `linux/arm64` |
| `speechnexus-node-controller` | `sha256:42da3e0a7182c8a15e859fb8c16cedd2e91630d6f2f066d534e341718da856bd` | `linux/amd64`, `linux/arm64` |
| `speechnexus-asset-inspector` | `sha256:a6d28845341b858b66e19028dd868493ae3a60f69d91e72f82fef0c30a068799` | `linux/amd64`, `linux/arm64` |

独立 arm64 机器（MacBook M1）在另一条链路上读到的 `v0.1.0` 标签 digest 与上表逐位一致；五个 arm64 镜像的 config 均带 `org.speechnexus.release.tag=v0.1.0` 与 `org.speechnexus.source.commit=d84ff9ef6e9fe4456670a8e436e6d19608e0ef75`。该链路是可达镜像站，不能替代 `ghcr.io` 的按 digest 拉取。

## 未核验（仍只有构建机证据）

独立 arm64 机器没有可用的 Docker daemon（Docker Desktop 在无 GUI 会话里无法启动），且该机 GitHub/GHCR 出网被本机网络策略阻断（TLS reset），三个发布附件一个都没取到。因此以下项目**没有**在独立机器上取证：

- 按发布 digest `docker pull` 并 `docker image inspect` 记录实际架构；
- 用发布 compose 文件起最小服务集；
- 迁移、`/healthz`、`/readyz`、`/v1/nexus/version`；
- 无 binding 时创建返回 `422`（而非 `500`/`503`）。

补做条件：宿主提供可用 Docker daemon 与 GitHub/GHCR 出网，或预置三个附件与五个 `linux/arm64` 镜像 tar（附可核验哈希），在同一台 arm64 机器上重跑上述四项。

## 操作提醒

`ghproxy.cn` 这类加速站对 GitHub 路径会返回 `200` 但内容是停车页 HTML。任何下载都必须校验文件类型与哈希，不能把 HTTP 200 当作成功。

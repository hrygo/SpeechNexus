# Issue 证据与状态

PR 合并只是集成事实。任务、AC、GitHub state 和标签分别核对；本文件不授权需求裁剪、创建标签或修改原生关系。

## 判定证据

实施任务的检查项对应具体 PR、制品版本、检查运行或报告，说明与判断相关的 revision、环境、时间、结果和覆盖范围；小修正可以共用一条明确覆盖相关 AC 的证据。外部报告按问题与预期结果核实，文档/答疑可用文档差异或明确结论，不凭空增加工程验收。历史勾选、完成声明、绿色 CI、issue 已关闭和 closing keyword 本身不是 AC 证据。

契约、fake、组件、浏览器冒烟、真实引擎和目标拓扑证据各有边界。单库、跳过、逻辑集群、合成媒体不能替代 AC 明确要求的双库、真实执行、物理拓扑或质量。分支 CI 不冒充合并后验证；交付被回退或证据版本失效时按当前有效事实判断。

只同步 issue 时复用已有有效证据，缺证据就保留待验证，不扩成业务实现、模型加载或运行态变更。未被本 PR 影响的有效历史证据继续保留。

对一个 PR 完整解决的小 issue，按其实际 AC 判断证据是否充分；适用于已合入内容的既有测试、审查或复现结果可以复用，并如实注明验证版本与环境。AC 未要求额外部署、真实引擎、物理拓扑或合并后复验时，不人为新增这些关闭门槛；已有明确要求仍须满足。

## 按现有方式维护状态

GitHub state/关闭原因表示生命周期；普通报告可只使用这些原生字段。Projects 已承担工作状态时沿用其字段，不额外引入同义标签。仅正文模式不改 state 或元数据。

下表仅适用于现有实施编排或已经使用 `status:*` 的项。授权覆盖标签维护时，活动实施项保持一个现有状态标签，完成项使用现有 `status:done`；普通反馈没有标签不构成缺陷。缺少目标标签时报告差异，继续可独立完成的正文/state 同步，不擅自创建或迁移状态体系。

| 标签 | 使用条件 | GitHub state |
| --- | --- | --- |
| `status:planned` | 尚未开始，输入尚未齐备且未形成当前关键下一步的实际阻塞 | `open` |
| `status:ready` | 具名开工输入齐备、尚未实施；不表示运行能力 ready | `open` |
| `status:in-progress` | 已完成部分实施，仍有实现工作 | `open` |
| `status:integration` | 本范围实现已交付，仍需生产装配、消费者接入或联合联调 | `open` |
| `status:qualification` | 相应集成已完成，仍需行为、质量、故障恢复或目标拓扑验收 | `open` |
| `status:blocked` | 关键下一步被明确前置阻断，正文写具体制品、负责人、影响与解除条件 | `open` |
| `status:done` | 完整范围、任务、全部 AC 及适用退出条件均有证据，无本范围遗留工作 | `closed` / `completed` |

状态按实际剩余工作选择。常规小 issue 在单个 PR 完成全部范围与 AC 后，可从当前状态直接到 `done`，中间标签不是必经流程。仍有实现就保留 `in-progress`；只缺联调或资格时分别使用 `integration`、`qualification`。部分路径待依赖但其他工作可推进时，不把整包标为 `blocked`。

## 关闭、重开与父项

- 解决问题或完整验收后以 `completed` 关闭，已采用标签体系的项同步现有 `status:done`。明确不计划、取消或不在范围内可用 `not_planned`，保留决定依据，不标记为已交付。
- 重复问题须链接主 issue。当前接口支持时用 `duplicate` 与已核实的重复目标；REST 的 `duplicate_issue_id` 是目标 issue 的数据库 ID，不能填显示编号。工具不支持时使用可用关闭原因并明确说明重复，不猜字段或为了改原因先重开。
- 已获分类/关闭授权时仍须区分上述原因；合并收尾本身不授权拒绝需求、取消范围或另行批量去重。重复或不计划关闭的项，授权覆盖标签时移除误导性的活动/`done` 状态标签，保留其他分类；不为它们新建状态标签。若缺这部分授权，只报告不一致。
- 缺信息时指出具体待补项；没有回复、没有进展或不符合模板不是本技能自动关闭的依据。
- 单 PR 已完整解决且 GitHub 正确自动关闭时保留关闭；核对正文、任务/AC 与状态标签，只补缺失项，已经一致就不写入。只有确认误关才进入重开判断。
- closing keyword 可能自动关闭未完成 issue。读最新正文、关闭事件和后续证据，确认误关且授权覆盖状态维护后重开；人工关闭、重复、取消范围或原因不明时提交具体建议，不自动重开。
- 工作包按完整范围关闭；早期 Gate 仅判断本阶段具名交付和前置，不要求所有持续交付包整包关闭，也不能据此提前关闭这些包。
- Gate 核对联合验收、前置与放行条件；Epic、总控分别核对自己的退出条件。父项只汇总本层变化，子项关闭不自动关闭父项。
- 依赖方仅在所需接口、版本或制品确实可用时更新前置；生产者合并不代表消费者已经接入，也不自动解除整包阻塞。

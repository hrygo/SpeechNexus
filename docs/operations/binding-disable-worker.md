# Binding disable worker

The worker scans durable disable roots for one explicitly configured gateway/node pair. It captures original gateway submit identities, requests the idempotent abort, and separately asks the existing lease transaction to settle each matching unreleased lease. An unknown or quarantined execution stays pending until the existing transaction can establish its required evidence; an abort request is not proof of stopping.

Provision two distinct non-owner PostgreSQL login roles in the **same** database and schema. Apply `disable_coordinator_grants(schema, scanner_role)` and `disable_settlement_grants(schema, settlement_role)` from `speechnexus_backend.speech.infrastructure.binding_disable_targets_schema` as the migration owner. These functions return SQL for an operator to review and execute; the worker never grants itself privileges. The settlement role needs the exact authority declared for the existing release transaction and must not inherit the scanner role. The scanner role must not inherit the settlement role. Both are checked at startup, including forbidden extra table or column privileges. The startup check requires both connections to reach the same PostgreSQL database and server.

Configure `SPEECHNEXUS_PROCESS_ROLE=binding-disable-worker`, `SPEECHNEXUS_DISABLE_DATABASE_URL` for the scanner, `SPEECHNEXUS_DISABLE_SETTLEMENT_DATABASE_URL` for the settlement role, `SPEECHNEXUS_DATABASE_SCHEMA`, `SPEECHNEXUS_DISABLE_GATEWAY_ID`, `SPEECHNEXUS_DISABLE_NODE_ID`, `SPEECHNEXUS_EXECUTION_GATEWAY_BASE_URL`, and `SPEECHNEXUS_EXECUTION_GATEWAY_COMPONENT_CREDENTIAL`. Configure the bounded `SPEECHNEXUS_DISABLE_GATEWAY_TIMEOUT_SECONDS`, `SPEECHNEXUS_DISABLE_STORAGE_TIMEOUT_SECONDS`, `SPEECHNEXUS_DISABLE_POLL_SECONDS`, `SPEECHNEXUS_DISABLE_BATCH_SIZE`, and `SPEECHNEXUS_DISABLE_WAIT_TIMEOUT_MS`. Store credentials using the deployment's approved secret mechanism. Run with `python -m speechnexus_backend.binding_disable_worker`.

A pass revisits durable roots and pages matching gateway/node leases by original lease ID. The lease service serializes with gateway submit: no submit row under the lease lock permits release; a submitted or quarantined execution requires the evidence enforced by that service. An unknown release commit is queried by that same lease ID. Concurrent workers may revisit identities, but lease row locks and idempotent release decide the result. A successful pass or an empty page does not prove that all engines have stopped or that cancellation is complete.

If a gateway crashes after recording an abort dispatch but before sending it, the original outcome is unknown and the current engine adapter cannot safely replay the external abort. Keep the execution quarantined and its capacity held; recover using the original identity and verified node stop evidence as described in [reconciliation and recovery](reconciliation-recovery.md). Do not infer a stop from the abort receipt or automatically stop an entire instance without the required owner authority.

# Issue 正文规范

供 issue 日常维护与合并后同步共同引用；公共入口与生命周期见[贡献指南](../../../../CONTRIBUTING.md)，状态判定由相应工作流处理。本文件规定正文内容，不扩大远端写入授权。

## 先选择正文类型

- **缺陷报告、功能建议、提问：** 保留原表单或报告结构，以及问题、版本/环境、复现、预期/实际结果或使用场景。缺信息时写明具体缺口；不要求报告者填写实施任务、进度或 AC，不强制改写为四部分。整理时保留原文中的有效事实与关键讨论依据。
- **实施任务：** 使用下述四部分。接手外部反馈时，可在保留原报告的基础上附简短实施摘要；较大计划链接独立实施任务，创建与关联需有相应授权。仅维护原反馈时不自动建立新任务。
- **Epic：** 写明目标、范围边界、可验收成果、当前差距与接收条件；只汇总所需证据和进展，不复制所有子项。

模板位于 [`.github/ISSUE_TEMPLATE/`](../../../../.github/ISSUE_TEMPLATE/)。新模板的必填项只收集诊断或判断建议所需的最少信息；不预填未经核实的负责人、标签、Projects 或组织 issue type。中文、英文报告均保留原语言。

## 实施任务的四个部分

| 部分 | 内容 |
| --- | --- |
| `目标` | 要解决的问题、完整交付结果与必要范围边界 |
| `进展总结` | 已交付/已集成/已验证事实、仍缺实现或接入、关键风险、阻塞及解除条件；链接证据并明确未提交、未集成、待验证 |
| `任务清单` | 可执行、可勾选的实施步骤；已交付步骤须有依据，较大独立工作在授权内拆子 issue，未获创建授权时提出建议 |
| `验收标准（AC）` | 可观察的行为和结果，按风险覆盖正常、失败、边界、并发与恢复；保留阈值、版本和拓扑要求 |

任务与 AC 分开维护。任务勾选表示步骤完成，AC 勾选须有对应验收证据；PR 合并、绿色 CI、fake 或组件测试不自动完成业务行为或目标拓扑 AC。混合要求仅部分完成时保持未勾选，说明已完成与剩余范围；拆项时保留等价的全部要求。

使用“已交付……”“已集成……”“尚未接入……”“完成……后验收”等直接语态。事实不确定标待验证，不把编辑者描述或未经核实的完成声明写成现状。时效性结果注明核验日期；需要具体时刻时带时区（项目记录默认 `Asia/Shanghai`）。合并日期与验证日期分别表达。

## 日常小 issue

默认一个边界清晰的问题由一个 PR 完整解决并关闭。四部分可以分别只有一句话或少量检查项；任务与 AC 仍分开，不为凑篇幅增加步骤。AC 只规定本问题所需的可观察结果和相关风险，不机械套用大型工作包的全部拓扑、质量或阶段要求。

实现和 AC 验证随该 PR 完成，合入主干后即可关闭；原要求已有额外验收条件时照常满足。问题确实跨多个 PR、模块交付或联合验收时才拆分；新项目 issue 原生直属一个已有主 Epic，不为小 issue 增设中间层。

## 层级与依赖

总控 #336 下十个 Epic 是产品范围入口；新项目 issue 原生直属唯一主 Epic，跨 Epic 的协作或依赖不重复建卡。需求矩阵覆盖完整范围，当前实施 issue 可为空；外部反馈由维护者按授权分类关联，保留原始报告。

- Epic 汇总目标、范围、成果与接收条件，不复制所有子项；子项关闭不自动代表 Epic 已验收。
- 通用完成要求集中引用；负责人、里程碑和状态等元数据使用现有 GitHub / Projects 字段。核对原生父项、依赖方向与当前能力，正文链接不替代父子关系；不猜测字段 ID。
- 依赖写明所需接口、版本或具名制品；真正阻塞时写清负责人、影响和解除条件。其他路径能推进时不把关联引用一律设为整包阻塞。

## 保持当前摘要

每轮就地替换、合并与去重，不按 PR、日期或轮次增加平行章节、折叠历史和重复检查项。原始报告、重要决定与有效验收证据继续保留，当前失败、未决问题与阻塞不能被成功摘要覆盖。只整理正文时不改写或删除历史评论。

同一结论保留当前有效的 PR、报告或证据索引；命令输出、测试明细、截图与 SHA 清单链接到已有来源，避免反复追加相同评论。已授权发布的重要决定、重复目标或关闭理由可用简短评论记录，并在当前摘要引用。唯一验收证据无可靠外链时保留最小可追溯摘要；不因压缩丢失要求、证据或失败路径。

实施任务的进展通常 1–2 条即可，较大事项通常 3–5 条，不凑条数。进展总结以 600 字符、完整正文以 6000 字符为项目的软预算，包含 Markdown、链接与折叠区。整理已有长正文时比较新旧长度并收敛重复证据；新增必要复现、验收条件或决定可合理增长。超预算先去重，仍需保留时在交付中说明原因，不把统计写进 issue。预算不用于截断报告、删除 AC、降低阈值或拒收外部反馈。

仅正文整理依据现有描述及其证据，保持元数据不变。发现矛盾保留未决事实并指出待澄清项；改变范围须有授权，并同时调整目标、任务与 AC。

## 工作方式

- 按派发方给出的目标、候选、写入范围、验收条件和资源窗口执行；产品排序与派工由承接会话负责。本角色不另建队列、不自行派工、不创建其他 agent、skill 或定时任务；无可推进工作时交回结果并结束，尊重暂停、权限和成本限制。同一写者同时只推进一个切片，项目合计最多两个无写冲突开发切片，共享主机窗口由承接会话确认。
- 处理候选仓库前读其根 `AGENTS.md` 和目标目录规则，只加载相关材料。只写指定文件；遇到并行修改先核实，不覆盖未知改动。commit、push、建 PR、合并、发布及运行态变更沿用明确授权。具备能力时作者负责提交、草稿 PR 和原 PR 返修；只能回传时由预定集成写者核验接入并承担该路径。
- 模型、工具、环境和权限以宿主与当前任务为准；继承受管 HOME、工具入口和缓存，不改共享配置或绕过拒绝。在实际执行位置核验必要工具、独立依赖、缓存及产物接收路径，复用未变化的有效回执；同因状态或权限失败保存诊断交具名责任人，原因未修正不重试。
- 使用合成或最小脱敏数据；真实音频、转写、声音参考和凭据不进提示、附件、公开仓库。只用获准的隔离服务，保护共享数据库、模型与其他任务。

## 交付与收尾

- 报告候选版本、可取得的成果 / 证据、实际检查、失败 / 未验项和下一接收人；区分技术阶段接收、产品 AC 与合并授权。已授权 PR 交付的代码阶段交精确 head 的待合并 PR，其他任务按约定成果接收，不扩大 Git 授权；验证 / 调查交报告和原件，不强制 PR。版本 / hash 无法自行核验时由宿主提供，不补造证据。代码修改交适任非作者审查；协议、协调事务、恢复、停止或预算释放的高风险改变须非作者独立审查与对应环境验证。
- 被指定为 reviewer 时，按派发方给出的固定候选核验，结论包含受检版本、依据和限制；接受或返修由承接会话记录到 issue / PR，不冒用他人身份改状态，也不另建审查队列。
- 完成、失败、取消或被替代时，在原任务交代工作区与成果去向。确认原执行停止、回传及必要文件收尾后，交付负责人安排获准操作者清理并同步记录；不自删活跃 cwd。保全独有修改、新文件和未知 ignored 内容，仅排除确认可重建的缓存。文件清理与业务 / 费用结算分别记录；保留项注明对象、负责人、原因、成果位置、解除条件和下次复核时间，默认 24 小时内复核，期限不是删除 TTL。细节按候选仓库 `docs/operations/agent-delivery-sop.md` 涉及部分处理。

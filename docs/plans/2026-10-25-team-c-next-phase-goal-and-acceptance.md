# 团队 C 下一阶段目标、实施路径与验收标准

基线：`base_sha` = `4b08c396c0fe8fc43c7e85683e534befab6bb22b`；交付 PR：[#153](https://github.com/hrygo/SpeechNexus/pull/153)（493 文件，未做 rebase，`main` 领先 54 个提交）。

## 一、现状判断（作为 C 负责人）

一句话：**C 侧"能不能跑、跑得对不对"已经基本证明完，"真不真"这一层整体卡在 A 与 B 的具名制品上。**

- **已证明**：工作台契约与绑定、九份工作包（issue #35–#43）对应的生产页面消费者与后端应用层、以及每一条操作的正/负/边界/恢复行为，都有可追溯证据（页面 597、单元/契约、隔离 PG **418** 含真实 Chromium 门禁、合成探针、真实本机 LLM 两例）。
- **未证明**：任何需要真实语音执行、真实设备、真实远端实时、真实部署与迁移、GPU 拓扑的结论——这些**不由 C 决定，也不能由 C 声称**。
- **风险形态已经变了**：早期风险是"页面没做完"，现在的风险是**证据失真**——把合成当真实、把"存在但无人运行"当"已验证"、把未解释的失败写成"通过"。本会话三次撞上这个风险，处理方式已固化成守卫。

### 三条教训（写进流程，不再重复犯错）

1. **"存在但无人运行"≠"已验证"。** 12 个探针此前能手工跑通却不被任何门禁调用；现全部接入，并新增守卫：C 侧探针要么被运行、要么必须在显式欠账清单里写明域与原因，清单过期即失败。
2. **诊断必须自带定位。** 探针只抛 `Unexpected synthetic route` 时，定位靠猜；改成带方法与路径后**一次运行**即锁定缺 `GET /v1/workbench/projects`。同理，探针失败时不得吞掉自己收集的证据。
3. **不解释的失败不许被"修绿"。** 最后一个陈旧探针在按应用意图补上重放后仍不回恢复，且证据排除了两类原因（服务端无拒绝、重放确已发生）；据此**既不记为通过，也不记为缺陷**，保留为唯一欠账。

## 四、实施路径

### 阶段 1（立即，纯 C）：把"体验与证据"补到无死角

1. **辅助技术实测**：用 macOS VoiceOver 与"减少动态效果"逐页走查（项目/稿件、会议纪要、助手、有声书、提词、文件转写、文本配音、实时字幕/配音、Admin 诊断与任务中心），记录实际播报内容与焦点顺序；发现重复播报或缺名立即修，并补单测固化（沿用本轮 `部署提词快照` 的做法）。
2. **诚实态矩阵**：对每个页面枚举"未配置 / 未启用 / 结果未定 / 被拒 / 冲突 / 配额"六类状态，逐一确认界面**不显示成功**且给出下一步动作；缺失的补 UI 与用例。
3. **契约一致性巡检**：把"每个绑定操作都必须有生产消费者 + 至少一个负例"做成测试（已有消费者普查方法可直接复用）。
4. **陈旧探针清零**：修完 `workbench-manuscripts-probe`（从本轮新增的诊断输出出发）或提交退役申请；退役需明确授权。

### 阶段 2（A/B 制品就绪即接入）

## 五、验收标准（AC）

**全局完成条件（不可放宽）**：只有 C00–C08 全部约定范围、生产消费者及必要真实验证**均有可追溯证据**，本目标才算完成；页面完成、fake 通过或 PR 合并**不能**代替真实验收。

| 目标 | 可观察的验收标准 |
| --- | --- |
| G-C3 | 每个页面的辅助技术走查记录包含：实际播报文本、焦点顺序、发现的问题与修复提交；"减少动态效果"下无动画残留；六类诚实态逐条有用例且**至少一条**断言"不显示成功" |

## 六、风险与红线

- **不得越界宣称**：C 不代替 A/B 宣称专业资格；不关闭 G0–G5；合成证据不得用于推导真实结论。
- **不得修绿**：无法解释的失败保持为失败并记录"排除了什么"；退役需授权。
- **不得污染**：业务内容与派生内容不离开部署网络；LLM 默认关闭且无公有云回退；日志与 fixture 不含真实凭据、私有音频、完整业务转写或音频 Base64。
- **并行改动**：本阶段基线交付未做 rebase，合并前需与 `main` 的 54 个提交对齐；对齐时保留他人改动，不用回退或整文件覆盖。

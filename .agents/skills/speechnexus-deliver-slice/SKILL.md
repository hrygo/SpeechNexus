# SpeechNexus 业务切片交付

将一个用户可观察结果做成可运行、可恢复、可复验的正式链路。实施时补齐链路，审查时报告缺口；只要求分析或整理材料时保持只读。

## 按任务确定深度

- **实施切片**：查清当前断点，完成授权范围内的实现、正式接线与验证。
- **交接或验收**：核对交付物和证据是否覆盖原要求；不给缺失条件补想象，不顺手实施。
- **局部修改**：例如文案、样式或已定位的内部修正，按改动做最小充分验证，不扩展为跨层审计。

## 先建立一条真实链路

1. 用一句话描述用户动作、目标结果、失败时应保留的事实。以当前用户要求及有效 AC 固定范围；并列条件分别保留，不为适配已有实现缩减范围。
2. 从本仓库 [AGENTS.md](../../../AGENTS.md) 的按需阅读表选择相关入口；协议看[契约索引](../../../contracts/README.md)，模块边界看[目录与依赖](../../../docs/architecture/repository-layout.md)。核对实际源契约、生产者、组合根和消费者；索引中的状态摘要可能落后，不能独立证明实现现状。
3. 沿 `用户入口 → 生成/校验边界 → 正式路由 → 应用用例 → 权威存储/执行方 → 结果读取/展示` 找首个断点。组件存在、可注入 adapter、生成客户端存在，均需继续核对正式装配是否实际使用。
4. 将断点分成可独立完成的本方工作、具名依赖、验证资格缺口。依赖写清 owner、接口/制品、版本或摘要、解除条件和受影响条件；一个依赖不就绪不自动阻塞整包。

链路或验收证据较多时才使用[切片映射与证据判定](references/slice-evidence.md)，简单切片可直接在现有任务中记录。

## 完成最小闭环，保留完整目标

- 优先打通一个有实际价值的正常路径，并同时处理该路径的关键失败/恢复行为；临时缩小验证范围须标为局部进展，不能变更原 AC。
- 新行为先对齐生产者和消费者的机器契约，类型及运行时校验复用生成入口。跨字段身份、版本和状态语义仍需行为断言。修改协议时，按[HTTP 变更规则](../../../docs/architecture/http-contract-change-checks.md)核对升级影响；升版本本身不豁免发现。
- 保持工作台通过公开语音协议消费底座；实现路径和表所有权由当前架构决定。缺少生产接口时交付明确依赖，不跨模块直写表或接管引擎来绕过。
- 涉及未知提交、取消、异步发布或持久恢复时，明确原身份、提交边界和权威事实。需要细化故障推演时可使用 `speechnexus-recovery-design`；它不是所有切片的前置条件。
- 检查正式入口能否到达目标行为，展示状态能否区分草稿、缓存、未知和权威结果。未交付能力不填入虚构遥测或成功回执。

## 用能证伪的验证支持结论

从 AC 选择断言及执行环境，再选测试入口；命令按 [AGENTS.md](../../../AGENTS.md) 和[当前 CI 规则](../../../docs/architecture/ci-validation.md)取用，不在技能内复制工具版本和完整命令清单。

- 正常路径验证用户结果，失败路径验证副作用、原身份、历史和恢复；优先使用足以暴露错误实现的断言。
- 核对测试是否实际执行消费者/子进程，以及是否使用正式装配。收集到测试、引用脚本、进程退出零或聚合数量都不能单独证明业务行为。
- 对容易虚假通过的门禁，按风险加入反例：移除实际调用、返回错身份结果、绕过正式装配等，确认门禁确实失败。无需为每个低风险变更制造 mutation。
- 分别说明合成、真实服务/持久化、模型质量、物理设备和目标拓扑覆盖；这些维度不能互相替代。跳过、不适用、失败和未知不记作通过。

交付时给出：实际完成范围、证据及限制、剩余条件和下一步。任务完成与 AC 通过分别判定；部分切片完成不结算整个工作包或 Goal。

## 保持技能耐用

当前事实从源契约、正式装配和实测取得；技能只维护判断方法。引用失效时定位替代权威入口并说明缺口，禁止沿用旧状态推断。新增规则应来自可复现的错误决定；用 [evals/evals.json](evals/evals.json) 的行为场景回归，运行记录放仓库忽略目录，不把测试数量或当轮 SHA 固化在技能里。

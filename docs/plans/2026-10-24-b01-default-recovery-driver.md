# B01 默认恢复进程装配

开工基线 main `22d50ee`，先整合 `9d927f5`、交付前再同步 `cafc6b9`，承接 #123 的可信节点来源和 #124 的连续扫描/互斥报告。
目标是让实际网关进程在有效受限配置下自动恢复原执行，不需要人工调用 sweep。
本单元不完成 B01 或 B00–B07 的完整真实资格。

## 冻结的方案

1. [内部配置机器契约](../../contracts/internal/gateway-recovery.schema.json)经原生成器导出
   Python/TS校验入口。固定节点私网IP、CA、不可变绑定与有界预算；节点凭据为独立Secret设置，
   不放入配置JSON。JSON全部显式填写，不自动填默认值。
2. 原恢复服务依赖窄查询端口：真实引擎观察服务仍可注入，默认组合使用原只读执行查询，
   不引入生产fake引擎或重复状态规则。完整节点双证据沿用原record_stop，A仍独立归还预算。
3. 单线程、单活扫描服务保留本地游标。轮询间隔用Event等待；逐行检查停止/单调预算。
   正在执行的数据库/TLS调用在自身期限内结束后才关闭pool/入口所有权，不能丢下线程继续写入。
4. 缺配置沿用原行为；半配置/非法配置拒绝启动。固定错误日志不包含原异常、端点、文件路径、
   凭据或正文；循环存活仅是运营条件，不是引擎readiness或模型资格。

## 验收

- 共享源/Python/TS正负配置样例，非法类型/范围/地址/身份/额外字段及不插入默认值。
- 原生生命周期、轮询/批次/逐行停止、超时与安全停机；不重发业务执行、不直接退预算。
- 实际网关进程、TLS节点与SQLite/PG消费者只GET验证：半证据保持unknown和占用，
  released检查点完成后自动关闭共享执行；重启/错误来源/退出均保留原事实和清理边界。
- 相关双库回归、完整门禁与PR/合后CI；共享生成清单经#22机械集成，不改A事务/迁移。

真实ASR/TTS、warmup/ready持续监控、GPU/负载与物理多主机资格仍按原任务推进；35B不停，
集群要求不降低，不采用etcd或Redis权威，不自动关闭父包/Gate/Goal。

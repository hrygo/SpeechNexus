# Web 无障碍与对比度门禁

目标：补齐两个真实构建入口的自动无障碍检查，在 Web CI 内运行小规模 Chromium 测试；文档路由不启动浏览器。

- [x] 对真实页面运行 WCAG 2.2 A/AA axe 扫描，覆盖浅/深色和窄屏，记录失败再修复。
- [x] 用故意破坏的页面证明无标签控件、低对比度及键盘/焦点保护会失败；主题覆盖系统与显式选择。
- [x] 补充共享样式或语义的必要修复；不放宽阈值，不忽略整类违规。
- [x] 接入现有 Web 作业；浏览器仅本机回环、无后端/模型，保留失败报告。
- [x] 本地针对性及完整 Web 验证、独立复核完成；托管 CI 通过后合并（交付结果以 PR 状态为准）。

范围：当前 AdminUI 与 Workbench 工程外壳。自动检查不能证明屏幕阅读器完整体验、所有业务页面或全部 WCAG 成功条件。浏览器实测优先于 CSS 文本或 jsdom 推断。

依据（2026-10-25）：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[对比度阈值](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[Playwright 无障碍测试](https://playwright.dev/docs/accessibility-testing)。普通文本 4.5:1、大文本 3:1；必要非文本视觉信息 3:1。装饰性资源不冒充业务图形。

实测：初始页面检查复现浅色徽标 2.93:1、警示文字 3.84:1、深色弱化文字最低 3.74:1，以及跳转链接未迁移焦点；必要修复后 29 项浏览器测试通过，504 次语义色对测量最低报告值 4.85:1。204 项 CI 回归、39 项 Token 回归、1121 项原有 Web 测试及格式/lint/typecheck/build 通过。自动结果与渐变人工复核边界见 CI 维护说明。

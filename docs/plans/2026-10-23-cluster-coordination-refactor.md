# 集群协调重构计划

状态：精简 DDL、事务机器契约、详细应用方案、权限工具与真实双库测试原型已交付；
生产业务接入、完整生命周期和集群故障资格尚未完成。
依据为 [ADR 0006](../decisions/0006-cluster-coordination-and-storage-portability.md)。
终审的触发器权限、来源校验修复完整保留在历史 SQL fixture；
兼容比较器与回归继续保留，未被本次重构覆盖。

本次按“实施重构，程序部分生成详细方案和契约”的授权，修改契约、工具、测试与
DDL 草案；程序接入顺序和精确事务步骤见[应用事务方案](../architecture/coordination-transactions.md)。
没有新增业务服务、路由、Worker 或引擎实现。

## 固定边界

- 集群部署是硬要求。单节点与多节点复用角色、协议、状态机、租约和恢复机制。
- 不采用 etcd；Redis 仅为可关闭的非权威缓存或通知，不形成数据库双写账本。
- PostgreSQL 为唯一正式交付数据库；MySQL/InnoDB 是关键协调行为的验证对象。
- 完整配方准入、持久幂等、fencing、停止证据、隔离预算、不可反转终态继续成立。
- 公共和内部机器契约继续有效；新增事务端口不得复制一套独立状态或错误词表。
- 跨表业务规则由受控应用事务保证；数据库仍保留基础约束与最小权限。
  绕过入口的任意直接 SQL 不再具有“全部跨表违例必被数据库拦截”的保证。

## 目标结构与职责

领域层计算预算、检查状态转换和停止证据。应用用例在受控事务中核对当前事实、
执行领域规则并提交。适配器只负责数据库操作和并发语义，不各自实现一份业务策略。
API 与 Worker 不能绕过执行网关；工作台仍通过公开语音协议消费底座。

| 原子职责 | 写入所有者 | 需要冻结的行为 |
| --- | --- | --- |
| 资源池 owner 获取与续租 | Speech Scheduler | 数据库时间、版本冲突、租期、单调 token、过期后重新获取 |
| 完整配方准入与预算释放 | Speech Scheduler | 参与资源版本、六维预算、全部 stage、隔离账目和停止证据 |
| Job/outbox 认领与恢复 | 各任务所属模块 | 幂等身份、认领版本、owner、到期恢复及重复通知 |
| 提交屏障与执行证据 | Execution Gateway | 当前 lease/attempt/generation/token、唯一意图、未知外发结果和终态 |
| 用量区间追加 | 对应计量所有者 | 区间身份、部分重叠、样本水位、重放与硬输出上限 |

这些是职责划分，不要求建立独立协调微服务或通用后端插件框架。
按需定义小端口与明确事务边界，保持现有依赖方向和表所有权。

## 事务与故障语义

### 完整容量准入

事务外可选择候选实例和解析不可变配方。事务内按既有全局锁顺序、同表主键顺序，
重新核对 owner、token、池状态、节点/实例状态、generation、绑定/策略版本、
配额与六维容量；一次提交全部租约、预算投影及相关意图。任一条件失败整体回滚。
不同池使用同一物理节点时争用同一父预算，不能按池各扣一套独立容量。

读到的候选结果不构成准入证明。采用条件更新时，必须覆盖全部参与资源的前置
条件；不能只检查任务行版本，也不能部分提交后异步补账。
计数与租约在同一事务更新，后台对账用于发现漂移，不能代替同步防超卖。

### Owner 与任务认领

同一池只有一个有效 owner，不同池可分散到不同节点；多实例竞争采用事务和
条件更新。续租不能让已失效任期复活，重新获取递增 fencing token。
Worker 通过持久认领记录和版本条件竞争，冲突在有界、可安全重试的事务边界处理。
`SKIP LOCKED` 可优化分派，但普通条件认领路径也须满足同一语义。

### 提交与停止

网关锁定并核对租约和提交身份，先提交唯一 submit intent，再外发引擎。
外发丢响应、数据库提交结果未知、进程重启均先查询原意图，不凭错误自动重做计算。
结果重放采用既有 Operation/receipt 恢复契约。

网关先用自己的事务提交停止证据，Scheduler 再用自己的事务核对全部附属执行、
关闭租约并释放预算。TTL、断线和心跳仅触发协调。旧入口未封锁或执行未知时继续
quarantine；不因换 owner、generation 或 attempt 清空占用。

### 数据库故障与恢复

所有适配器要求单一权威写入端及已确认协调记录的持久性。连接失败或提交确认丢失
须保留不确定结果，通过原幂等身份恢复。主备切换或备份恢复后，若 token、水位、
租约或执行历史完整性不确定，先停止新准入、封锁旧入口并协调在途执行；
不得仅切换连接串就恢复接单。删除账本重放与内容恢复屏障继续遵守原契约。

## 数据库能力与适配范围

必须真实验证多行事务、回滚、唯一约束、条件更新和受控锁定。
隔离级别名称相同不等于并发行为相同；由适配器实现共享事务契约。
跨库验证还覆盖大小写/排序、NULL 与唯一性、整数及乘法溢出、时间精度、
数据库时间、受影响行数、死锁重试和提交结果未知。

不依赖 JSONB 查询、数据库通知、GiST、部分索引或数据库过程执行业务规则来证明
协调正确性。公开 JSON、数值与摘要仍按契约往返校验。
本次真实环境为 PostgreSQL 16.15 / psycopg 3.3.6 与 MySQL 8.4.8 / PyMySQL 1.2.3；
驱动已锁入 `uv.lock`，MySQL 仅加入开发/测试依赖。两库基线均为 Read Committed。
MySQL 验证只使用项目隔离实例，不访问同机共享数据库。

## 集群与跨库验收矩阵

关键协调行为测试在 PostgreSQL 和 MySQL/InnoDB 运行相同期望，
每种数据库使用独立实例和连接。触发器负例不充当跨库行为测试的替身。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 两个 Scheduler 同池竞争、过期 owner 恢复 | 唯一有效任期；旧 token 不得新增提交或发布结果 |
| 多 Worker 认领同一任务、重复 outbox 通知 | 原任务身份保持；冲突可恢复；不因重复通知创建新执行 |
| 两个池同时争用同一节点最后预算 | 完整配方最多一方成功；另一方无部分预留，无跨池超卖 |
| 多阶段跨多个资源预留，中途冲突/崩溃 | 全部提交或全部回滚；无持槽等待形成死锁链 |
| submit 与 release、admission 与 drain、takeover 与 submit | 按确定交错验证两个先后方向，不以 sleep 或单连接代替竞争 |
| 外发成功后丢响应、持久提交确认丢失 | 查询原意图恢复；未知期间保留占用，无盲目重算 |
| lease 过期但引擎仍运行，Gateway/Controller 故障 | 隔离且保留预算，拿到停止和释放证据后才归还 |
| 旧 Gateway 暂停后恢复、网络分区 | 旧入口被有效封锁；无法证明时保持不可接管 |
| 实时 owner 故障与重连 | 沿用现有 epoch、样本缺口和显式恢复语义 |
| 输出部分重叠、重复样本区间、越硬上限 | 非法追加整体拒绝，精确重放不重复计量 |
| 主备切换/恢复后的 token、执行与删除账本 | 不复用旧任期，不恢复未知占用为空闲，不重新暴露已删除内容 |
| Redis 不可用、通知丢失或重复 | 持久轮询能继续发现任务，协调和容量事实不变 |

当前单机可用独立进程/容器模拟至少两个逻辑节点、两个 Scheduler、
多个 Worker 和 Gateway，验证竞争与受控故障。该结果须标记为单机逻辑集群验证。
跨主机网络隔离、节点丢失、目标数据层切换和实际吞吐需在相应环境验证，
不因当前只有单节点而删去验收要求。真实模型与引擎资格另按绑定/拓扑记录。

## 迁移和回退

当前没有业务运行态迁移。本节约束未来部署数据库或切换适配器时的操作：
先停止新准入，完成或隔离在途执行并封锁旧入口，再迁移身份、租约、
不可变版本、幂等摘要、fencing 水位和执行/删除账本，校验后切换适配器。
禁止旧新数据库同时接受协调写入。失败时保持暂停并恢复唯一权威，
不能靠重置 token、删除历史或释放未知容量完成回退。

## 验证入口与完成标准

现有入口继续使用 `make contracts-check`、兼容比较器、`uv run lint-imports`、
Ruff/mypy、针对性 pytest 及显式隔离 DSN 的数据库集成测试。
双库门禁为 `make coordination-test`，必须同时提供 `SPEECHNEXUS_TEST_DATABASE_URL`
和 `SPEECHNEXUS_TEST_MYSQL_URL`；缺任一变量直接失败。初始化与清理按测试独立
namespace 执行，命令见[集成测试说明](../../tests/integration/README.md)。CI 配置已加入
隔离 MySQL 8.4.8 service，但本地执行结果不替代尚未运行的远端 CI 结果。
协调变更须跑两种数据库的相关矩阵，缺 DSN、跳过或基础设施故障均不算通过。

完成标准是：所有目标集群行为不变，约定协调路径通过两种数据库真实测试，
PG 特定业务规则被明确替代，权限、证据、兼容性和恢复路径可审计。
不以减少表数、触发器数或 SQL 行数作为成功证据；只有原型测试不能宣称全产品
MySQL 支持、跨主机资格或业务运行时已经交付。

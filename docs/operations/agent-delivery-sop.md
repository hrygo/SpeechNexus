# Codex / subagent / Delegra 交付 SOP

适用于选择执行方式、跨会话接续及多 Agent 交付；简单局部任务直接执行，不为使用本 SOP 新建计划、任务卡或审批。产品边界与授权遵循[根规约](../../AGENTS.md)，职责与环境边界见[军团工作流](paperclip.md)，检查范围见[验证指南](../agent-verification.md)。本页规定协作方法，不宣称平台已部署这些规则或具备事件订阅能力。

## 一个目标、一位负责人、一条执行队列

- 唯一 SM+PO 按最新明确授权决定优先级、范围、AC 与产品接收；实际身份按部署映射核实，不从聊天标题、岗位名或组织树推断。其他会话和 subagent 只承担具名交付或独立审查。
- 每个可验收切片由一位交付负责人负责候选、修复、验证、交接、解阻和工作区收尾；会话内局部任务默认由当前执行者负责，无需另设岗位。这是技术责任，不增加产品排序权或二次审批层。总控可直接完成授权内的核查与修复，参与实现后仍须交适任非作者审查。
- PRD 保存完整产品要求，设计说明方案；GitHub issue 保存当前任务与 AC，Delegra 只保存当期执行切片、依赖和回执。会话内可完成的局部工作无需额外建卡；已有执行任务时沿用原任务，不在不同平台同时派发同一修复。
- 当前范围通过 [PRD](../prd.md)、相关设计和[需求矩阵](../plans/delivery-tracking.md)关联到[总控 #336](https://github.com/hrygo/SpeechNexus/issues/336)下十个 MECE Epic；[关联源](../plans/delivery-issues.json)保留稳定需求、主责、实现/集成/验证及证据。实施 issue 可以为空；使用[按需规划技能](../../.agents/skills/speechnexus-next-delivery/SKILL.md)选择下一可验收切片，新卡原生直属唯一 Epic，随后登记并只读刷新状态。不在 GitHub 或 Delegra 预建全部 backlog，历史仅在查证时读取。
- Goal 写明对应目标、获授权阶段的交付物、接收条件和停止条件。等待时保存恢复点；外部条件未满足不得宣称完成，也不靠自动续行反复查询或寻找无关旁支。

## 按反馈和环境选择执行位置

| 路由 | 适用工作 | 交付与约束 |
| --- | --- | --- |
| 当前 Codex 会话直接执行 | 局部修改、明确修复、需要用户即时查看或频繁纠偏 | 在同一候选完成必要检查；不因耗时长就另加管理层 |
| 当前执行者按需使用 subagent | 可独立的定位、日志分析、反证或文件范围清楚的实施 | 传明确问题、必要版本、读写范围与预期结果；返回结论、依据、未验项，不复制整段聊天和原始日志 |
| Delegra 持久任务 | 跨会话接续、专用 Linux / 数据库 / GPU 环境、资源窗口或正式制品交接 | 启动前确认输入可取得、能力与授权满足、具名执行者和接收者；密集的内部修复留给执行者完成 |

任务长短只是信号；按反馈密度、环境需求、可独立性和交接成本选路由，不要求三种机制每次全部参与。新建用户可见的 Codex 会话按用户请求执行，不把它当自动派生的后台工作单元。

subagent 的上下文、工作区、工具与权限以宿主实际能力为准，不假设它自动获得独立 checkout 或隔离环境。同一文件只有一名写者；需要并行检出时使用各自 worktree，数据库、端口和共享资源另行安排。Codex、subagent 与 Delegra 合并计算并发和主机窗口，沿用军团最多两个无写冲突开发切片及单岗并发 1 的限制；增加调用层数不增加额度。

## 最小上下文与执行步骤

需要交接时沿用任务正文和已有制品清单，仅补本次路由与风险适用的信息，不新增一套表单。直接回答不要求候选或 reviewer，纯文档不要求运行环境，无平台岗位不要求能力卡；不适用项不构成门禁。真正缺少的必要输入只阻塞依赖它的动作。

| 信息 | 最低需要 |
| --- | --- |
| 目标 | issue / AC 或用户请求、当前场景、预期结果、本次范围 |
| 候选 | 实际 base、目标分支、候选 SHA 或完整补丁及正式入口 |
| 责任 | 交付负责人、唯一写者与文件范围、适任非作者 reviewer、接收者 |
| 条件 | 执行环境、已有授权与资源窗口、必要检查和停止条件 |
| 恢复点 | 已完成、失败 / 跳过 / 未运行、证据位置、具体阻塞及下一动作 |

1. **确认目标与输入。** 只读本次相关规则、issue、版本和证据；同一会话复用仍有效材料，新会话按恢复点补读变化。历史原因用项目记忆，当前实现用代码与实测；不把历史结论作为当前状态。
2. **确认可执行。** 按实际动作核对版本、工作区、授权与所需资源；使用平台岗位时核对岗位运行与能力回执，使用专用环境时核对环境可用性及适用回执。已有同配置、同环境的有效回执可复用；首次使用、配置 / 环境变化或失败后再做最小预检，不为每次派工固定新建探针卡。涉及共享资源时仍须核当前余量。
3. **完成一个候选。** 作者在原切片实施、自测并修复问题；补验和返修更新同一清单。只有独立交付、责任人 / 环境边界或平台恢复确实需要时才拆子任务，记录输入和接收关系；单纯等待和重复检查不拆卡。
4. **按风险审查与验证。** 固定受检候选，非作者检查适用边界；高风险仍须合格非作者 Sol 与对应环境验证。代码评审与独立运行验收分别判断，subagent 或换角色名不自动满足作者、模型或环境独立性。独立运行验收按任务适用条件使用不同主机、不同数据库大版本或不同取码路径；同一环境原样重跑只记复测。
5. **接收并收尾。** 接收者实际取得候选与证据，核对版本和适用检查，按授权交付补丁 / PR、接入或合并。分别记录技术交付、AC 与 Gate；按下节清理临时工作区并交回执，合并后再次核查剩余分支与保留项，不额外建立长期队列或重复唤醒已结束任务。

## 工作区生命周期与收尾

工作区服务于当前交付，成果与恢复证据放在可独立取得的位置；任务结束后不靠保留整棵目录保存交付物。此处“工作区”同时涵盖 Codex、subagent、Delegra 的临时 worktree、独立 checkout 及隔离恢复目录，清理范围和权限仍按根规约及当前授权判断。

- **创建前核对。** 默认保留主工作区，每个实际在办、具名且无写冲突的开发切片最多一个临时工作区；沿用最多两个开发切片的总额度。只读 subagent 优先读已有候选；独立验收确需新 checkout 时，在原任务注明环境、负责人和使用窗口。重试或替换执行前先处置旧 run 与工作区，不绕过隔离另建副本。
- **原任务负责。** 创建时沿用原 issue / 执行卡登记路径或平台 ID、分支 / base 和交付负责人，不另建台账。执行者完成原进程与回传的收尾，接收者确认成果可取得，交付负责人负责最终清理；跨机器或无平台权限时指定具名操作者，不能把“已回传”当成已清理。
- **同轮处理。** 完成、失败、取消或被替代时即核查，不等下一批派工或阶段结束。PR 候选和独有文件已可靠保留、无运行或验收引用时，可在 PR 合并前移除本地临时目录；保留仍需使用的 PR 远端分支与证据。合并后按实际 head 与合并结果复核剩余本地分支，远端分支删除另核授权。

按以下顺序完成一次收尾，复用仍有效证据；纯读取且未创建临时资源的任务记“不适用”，不额外打包或建恢复卡。

| 步骤 | 必须核实与处理 |
| --- | --- |
| 1. 固定对象与停止证据 | 对齐项目、issue / run、工作区 ID / 路径、branch / HEAD 和现有使用者。核查 controller、provider / 子进程、bridge、回传及 Git 操作；任务终态、PID 消失或旧租约到期各自不能单独证明全部已停止。主工作区、用户保留项、其他任务及仍在用目录保持。 |
| 2. 保全独有成果 | 核验主线包含关系，或远端 PR 实际 head / 已接收候选；squash、旧分支或分叉进一步比较实际差异。保存 staged / unstaged 修改、新文件和必要 ignored 内容；需要恢复时保留 refs / bundle、索引及有价值的 mode / symlink / 扩展属性，校验摘要并按风险验证恢复。Git bundle 不替代文件备份，补丁不替代未跟踪文件。 |
| 3. 结清文件恢复 | 按原 run 身份核实回传、宿主接收、文件 finalize、租约释放及未决操作。已停止且文件可独立恢复时，允许如实完成文件收尾，同时保留业务失败、未知费用和有效恢复记录；不为清理伪造业务成功、complete 用量回执或零费用。 |
| 4. 清理与平台同步 | 优先使用所属应用的生命周期入口，按授权解除过期绑定、归档并移除临时目录；普通 worktree 使用 Git 支持的移除流程，独立目录优先可恢复地移入废纸篓。只删除有保留证据且无使用者的本地分支；不批量强删、不因远端分支消失就直接 prune。 |
| 5. 回读与交回执 | 确认原目录已移除、`git worktree list --porcelain` 无该注册、目标分支按预期处理、平台记录已关闭 / 归档且无旧活动绑定。保留仍有效的历史关联与业务 / 计量事实。平台归档但目录还在、目录已删但记录仍 active，均属于未完成的收尾。 |

清洁且提交已可靠保留的目录无需额外全量备份。只可排除已确认可重建的依赖与缓存；不能仅因文件被 ignored 就丢弃未知内容。证据、敏感文件和必要运行数据保存在获准的仓库外位置，不把备份混入产品提交。

隔离、回传或 finalize 卡住时，由具名平台维护者按精确身份修复原操作；没有关闭接口不是处置终点，应定位支持入口或提出可审查、可回退的定向维护。维护须保留停止证明、before-image 与审计，并遵守原锁 / fencing；本 SOP 不授权绕过平台权限、直接改数据库、清空 session、改预算或恢复调度。已停止的临时检出，在成果保全、文件回传 / 最终化与所需租约释放按原协议核验后，未知账务保留为账本中的独立待处理项，不单独构成无限保留目录的理由；仍依赖原目录的未决操作继续按具名例外跟进。

确需保留时，在原任务或既有交付回执写明路径 / 平台 ID、具名负责人、保留原因、成果保留处、解除条件及下一复核时间，默认在 24 小时内复核。时限是处理与升级要求，不是删除 TTL；到期仍未解除时，交付负责人推进具体修复或交 SM+PO 明确保留决定与新期限，不自动续期。接管及下一次派工前复核已有保留项；同一切片的旧工作区处置未明确前，不再启动其替代执行或创建新副本，无关独立工作可继续。

最终报告沿用一行：`工作区收尾：已清理 / 不适用 / 保留（对象、负责人、原因、成果位置、解除条件、下次复核时间）`。业务 issue 仍按完整范围与 AC 判断；业务已交付但资源尚未收尾时分别说明，不能宣称“全部完成”。用现有任务时间戳、交付 / 合并事件和下一次接管检查触发收尾，不因此安装新 timer、巡检任务或新增审批层。

## 同版证据与最小充分验证

- 每份结果绑定精确候选、相关契约 / 迁移 / 依赖、环境、命令与原始结果。候选变化记录新增差异及受影响结论，仅补验失效部分；无法证明仍适用的历史结果保持历史，不转算当前通过。
- 测试按既有命令和实际副作用分组确认边界，记录允许的子进程、文件、网络、隔离与清理。内存 ASGI transport 本身不等于启动监听服务；临时 loopback、子进程或数据库仍须在实际授权内。不能因措辞含混把整组安全测试永久挂起，也不能凭“测试”二字扩权。
- 分批执行维护同一份测试清单与累计覆盖；通过、失败、跳过和未运行分列，未运行项给具体原因及解除条件。已执行组无需每轮重报逐节点清单；定位遗漏或歧义时再展开，不把分批结果宣称为同版全套一次实跑。
- 制品在获准存储发布后供接收方按权限取得并核验；已有同版原件与有效核验可复用，不为每次转述重新打包、上传或全量复测。正式入口不可访问时交提供方 / 平台修复，不借他人私有工作区或绕过权限取件。
- 保留真实引擎、正式消费者、隔离持久行为和物理拓扑等原验收范围；平台接收附件、绿色 CI、局部 done 各自只证明覆盖范围。

## 等待、汇报与故障恢复

优先使用宿主实际可用的完成、失败或需用户处理事件。Codex 会话状态用支持的紧凑等待 / 快照；Delegra 未核实有可靠事件入口时，才在现有授权内做有界状态查询，记录下一检查条件。不新建 timer、轮询任务或反复读取完整日志；没有新事实时保持安静，持续工作仍遵循宿主必要进度沟通要求。

长任务在任务内约定与规模相称的进展检查点，报告已产生的候选 / 证据、剩余工作和阻塞，不只报告“仍在运行”。对用户在交付、关键验证结果、实质阻塞、风险变化或需要决定时汇报；保留失败与限制，不以消息频率代表进展。

配置、鉴权、工作区和平台错误由具名维护者处理；相同原因不循环重试。阻塞记录包含已确认事实、影响、责任人、下一动作与新证据要求；输入或原因改变后再续行，继续可独立完成的工作。

旧进程停止、checkpoint 或未决操作结果不明时保留隔离和原产物，不靠清空会话、换 Agent 或新卡重放。获准操作者先取得停止与操作结算证据，再决定原任务续行或带恢复点移交。平台只允许查看或要求用户处理时，任务授权不绕过该边界；本 SOP 不授权修改平台数据库、鉴权、权限、预算或运行配置。

阶段收尾利用已有时间戳、任务与费用记录比较：从就绪到可接收交付的时间、阻塞时长、重复交接 / 验证、返工和 Agent 费用；缺记录标未知。以可接收交付和遗留风险评估效果，不以任务数、报告数、活跃 Agent 数或测试总数证明效率提升，不新增常驻统计任务。

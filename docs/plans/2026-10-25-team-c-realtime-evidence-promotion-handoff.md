# 团队 C 交接：把既有的合成实时探针接入门禁，并更正我上一轮的过度断言

## 更正（先说错的那句）

上一轮交接与 issue #39 里我写了：

> "C04 的界面此前**没有真实浏览器证据**……C04 界面此前没有任何真实 Chromium 取证。"

**这句不准确。** 真相是：

- `scripts/dev-env/workbench-realtime-asr-probe.mjs`（2026-10-24）与 `workbench-realtime-tts-probe.mjs`（2026-10-24）**早已存在**，且都是自包含的：自带 loopback 合成语音生产者（`http` + `ws`）、用生产 `dist` 驱动 Chromium、不依赖 A 底座或真实设备。
- 但它们**没有任何 pytest 包装**，也不在任何门禁列表里——`--browser` 当时只列了会议、删除、真实运行时、稿件、助手、Admin、提词状态、有声书章节。所以准确表述是：**C04 此前没有"进入门禁、可追溯"的真实浏览器证据**，而不是"没有取证"。

把"存在但无人运行"说成"不存在"，会掩盖已有的工作、也会让后来者重复劳动。这正是本轮要修的东西。

## 本轮改动：把两份探针接入门禁

新增 `tests/integration/test_workbench_realtime_synthetic_probes.py`（2 个用例）并列入 `--browser` 门禁，实跑结果：

| 探针 | 结果 |
| --- | --- |
| ASR（合成实时生产者 → 生产包） | `passed=true`，**3 个合成会话、10 次已确认写入** |
| TTS（合成实时配音 → 本地渲染） | `ok=true`，1 个合成会话、5 次写入、**收到 48000 样本、渲染 48000（无丢失）** |

## 证据范围与边界（不得外推）

- 这两份是**合成生产者**证据：无模型、无物理设备、无语音底座，**不含**音频质量结论。
- TTS 的"渲染 48000"是**本地渲染水位**（AudioWorklet 已渲染），**不是**物理扬声器时延或听感证明。
- 覆盖范围仅 C 侧实时消费者的本地链路（握手、credit、文本确认、PCM 计数、渲染计数）；真实远端双向流、真实设备、权限拒绝/撤销、断网重连与长时行为仍未验证（owner：A/B）。
- 采集（`microphone-capture`）只经 `realtime-session` 被使用，而无实时底座时**不存在**已连接会话，因此"获得→排空→释放"的真实路径在本机仍**不可达**；本轮没有用合成设备硬凑这条路径（那会制造"看起来验过"的假象）。

## 门禁与结果

| --- | --- |
| 全量隔离 PG 探针（含 `--browser`） | **401 通过**（399+2，本轮新增两份合成实时用例） |

`ruff` 的 ASYNC240（异步函数里不得直接调用阻塞 pathlib 操作）先拦下了新测试里的 `mkdir`/`is_dir`；已把文件系统操作移到同步辅助函数，而不是用 `noqa` 掩盖。

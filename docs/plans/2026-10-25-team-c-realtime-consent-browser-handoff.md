# 团队 C 交接：实时字幕页的真实浏览器取证（未连会话绝不请求麦克风）

C04 的界面（实时字幕 / 实时配音 / 媒体采集）此前**没有进入门禁的真实浏览器证据**——本会话的探针只覆盖稿件、有声书、提词、助手与 Admin。（更正：`scripts/dev-env/` 里早已存在两份自包含的合成实时探针，但无包装、不在任何门禁，详见[合成实时探针接入门禁](2026-10-25-team-c-realtime-evidence-promotion-handoff.md)。）而这一页对使用者有一个明确承诺：

> "先创建并连接，服务完成准入后，**再由你明确开启麦克风**。"

承诺必须被验证，否则它只是一句文案。本轮用生产包 + 真实组合根 + 隔离 PG（**无实时底座**）加一份真实的 Chromium 取证，并且**不给浏览器麦克风**：把 `getUserMedia` 换成计数器，任何一次请求都会被记下。断言的是"零次请求"，而不是"请求成功"。

## 我连错两次的预期（记录以免重犯）

- 我先假定"行动按钮（连接/读取/开始采集/停止）应在未连接时可达"——**错**：无会话时这些控件根本不存在，"开始麦克风采集"更是**不提供**，这比"提供但禁用"更诚实。
- 我又假定"创建表单在无底座时被禁用"——**也错**：它是可用的，会被部署公开拒绝（404）。
- 于是把探针改成**发现驱动**：先记录页面此刻真实提供的控件与 Tab 顺序，再断言诚实性质（零麦克风请求、未连接不提供采集、拒绝被公开表达）。教训：**关于"页面此刻长什么样"的断言必须来自实测，不能来自我的想象**。

## 未验证与边界

- 这是**没有麦克风**的取证：合成/物理设备采集、真实远端双向流、权限拒绝/撤销、断网重连、长时行为均未验证（需 B/A 的制品与目标环境）；本用例**不能**当作设备或采集资格。
- 未覆盖实时配音页（`RealtimeTtsHost`）与本页的会话恢复分支。
- 浏览器为 macOS + 本机 Chromium，不代表 Linux 后端或目标拓扑。

## 下一接入动作

1. 以同样的计数器手法覆盖**权限拒绝**与**设备切换**：Chromium 支持 `--use-fake-device-for-media-stream`，可在无真实设备时验证获得/释放路径（并明确标注为合成设备）。
2. 实时配音页同样补一份真实取证。
3. 实时底座就绪（A/B）后，把"连接→明确开麦→排空→释放"的成功路径与 gap 语义接上真实证据。

# 工作台已提交内容下载

## 行为与所有权

`downloadSavedAsset` 和 `downloadBookExport` 经生成边界、C 业务路由、短 PostgreSQL
事务和 C 私有对象区读取已提交内容。下载不访问原语音服务，不返回对象 URL、桶、
内部路径或凭据。副本不随源制品过期；导出未完成返回 409，已过期返回 410。
不存在、其他 workspace 或已 tombstone 的项目返回 404。

对象完整读取到私有 `SpooledTemporaryFile`，校验已提交长度和 SHA-256，确认项目仍
可读后才发送成功响应头；Range 也校验整个对象。DB 事务不跨对象 I/O。源对象缺失、
长度或摘要不符、SDK 故障和准备超时统一返回无内部细节的 503。已开始发送的响应
遇到连接故障只终止传输，不能再改发 JSON 或撤回已传输字节。

完整读取的成本是首字节等待一次对象读取及摘要计算，但可在发送前拒绝损坏对象。
直接 Range 读取不能证明未读部分的完整摘要。本阶段优先保证已提交副本的整体一致性。

## HTTP 与消费者升级

canonical `workbench-openapi.yaml` 从 `0.1.0.dev0` 升至 `0.1.0.dev1`，在已有两个
下载操作中增加 400、408、413、416、500、503 JSON 状态；已有状态和可选头的
schema 保持接受范围。新增 416 必须带 `Content-Range: bytes */size`。这是旧严格 SDK
不认识的新响应状态；先升级并重新生成消费者，再部署下载生产者。升版本不能豁免
HTTP 结构检查；这次未改变其余 v1/v2 JSON 业务语义，也未实现导出 SSE。

服务端固定返回 `application/octet-stream`，200/206 包含真实 `Content-Length`、
`Accept-Ranges: bytes`、引号包裹的 `sha256:...` 强 ETag 和请求关联 ID；206 再带
精确 `Content-Range`。响应禁止缓存，不重定向到对象区。

支持单个闭区间、开放结尾和后缀区间；超出末尾会截到对象结尾，后缀大于对象时
返回整个对象的 206。空区间、反序和不支持的语法返回 400，起点越界或零后缀返回
416。不改变已有 Range 请求 regex 接受范围；400 在应用层处理 `bytes=-`。
长十进制范围先按字符串比较并截断，不对不可信超长数字调用 `int()`。
这些处理参照 [RFC 9110 的 Range 与 416 语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

正式 Web 消费者使用生成客户端的原生流，固定同源、禁止重定向、无自动重试。
只对已读取且身份固定的副本/成功导出启用下载；再次核对 200、长度、ETag 和完整
SHA-256 后才产生本地 Blob 保存动作。浏览器取消、视图卸载、读流错误或校验失败
不触发保存。浏览器 SHA-256 要求安全上下文；不可用时显示失败，不假报已校验。

## 有界执行与剩余资格

部署配置默认：`download_max_bytes=268435456`、`download_max_active=2`、
`download_timeout_seconds=120`。准备与响应发送分别有该时限。内存 spool 上限
1 MiB，超过后进入进程私有临时文件；每个响应有大小界限，每个实例有并发界限，
满载直接 503，不积累等待队列。取消/准备超时设置停止标记并等待工作线程退出，
再关闭缓冲、释放容量。原生 SDK 单次阻塞读取仍受连接 3 秒、读取 10 秒、池等待
3 秒约束；协作总时限不是抢占原生调用的硬上限。

响应整个 ASGI 生命周期的 finally 回收 spool 和容量，包括首个 body chunk 前断开。
准备后再次读取权威元数据，以最后一次读取作为可见性判断点，拦截此前已提交的删除；
该点之后的删除不撤回已准许的读取。它不承诺撤回已发送内容或新增全局读租约。
临时文件不充当跨进程制品或持久副本，只有对象区是内容权威。

浏览器单标签页同一时刻只校验一个下载，最大 256 MiB、网络/读取时限 120 秒，
可能同时持有多个有界内存副本；这不等于大文件、设备内存或长时容量资格。
服务端本地并发界限同样不是全局协调预算。完整导出清单、断点续作、全局配额、
正式保存音频的生产者、模型质量、目标拓扑和原 AC 的容量/故障资格仍须分别交付。
